# session-reader 开发规范

本文件规定 session-reader 技能（`SKILL.md` + `README.md` + `CHANGELOG.md` + `scripts\` + `tests\` + `doc\` + 工程文件）开发与维护必须遵守的要求与约束。

## 定位与范围

- 本技能只读 dsh 会话历史（`~\.dsh\sessions` 与 `~\.dsh\storages`）；除写入 `--output-dir` 指定目录内的输出文件外，禁止写入、删除或修改 dsh 主目录内的任何内容。
- 运行时禁止启动 dsh、禁止联网、禁止产生模型调用、禁止读取凭据文件（`.credentials.yaml`、`.env`、含凭据的 profile 补丁）。
- 技能范围限于 `SKILL.md`、`README.md`、`CHANGELOG.md`、`scripts\`、`tests\`、`doc\` 与工程文件（`package.json`、`package-lock.json`、`tsconfig.json`、`biome.json`、`.markdownlint.jsonc`、`.markdownlintignore`、`.gitignore`、`.nvmrc`）。技能根的 `tmp\` 是**非交付临时目录**（不受版本控制，且被技能根 `.gitignore`、`.markdownlintignore` 与 `biome.json` 的 `files.includes` 三处排除），其中不得存放任何被规范、测试或工具依赖的内容；需要长期保留的脚本或夹具必须落在上列交付路径内。

## 语言与运行

- 脚本语言为 TypeScript（ESM，`.ts`），使用原生类型剥离直接执行；禁止引入构建步骤或提交编译产物，使用 `tsc` 独立检查类型。
- 项目根提供 `scripts/run-npm.mjs`，开发依赖安装与项目任务均在项目根以 `node scripts/run-npm.mjs` 后接 npm 参数执行。agent 不书写 npm 的入口路径，也不直接执行 npm 的 `.cmd` 与 `.bat` 入口。
- 调用方使用 Node.js 24 运行唯一入口 `scripts/run-session-reader.ts`。入口复用 `scripts/lib/desktop-runtime.ts` 按结构定位 `%LOCALAPPDATA%/Programs` 下唯一包含 `resources/runtime/bin/node.cmd` 标记的桌面安装，直接启动安装根下与目录同名的可执行文件，仅为子进程设置 `ELECTRON_RUN_AS_NODE=1` 并传入 `--expose-internals`。入口以参数数组转发调用方参数，透传 stdout、stderr 和退出码。`node.cmd` 只是安装结构标记，不是执行入口。定位失败、候选不唯一或缺少可执行文件时显式失败，不使用备选路径。
- 官方格式库位于同一桌面安装的 `app.asar` 虚拟路径，业务 CLI `scripts/session-reader.ts` 必须在桌面版 Electron-as-Node 中运行。系统 Node.js 24 负责运行启动入口，不直接运行依赖该归档路径的业务 CLI。
- 调用示例必须注明执行环境；参数化进程入口将可执行程序及参数按值传入，不经过 shell。`run_code` 示例必须展示完整调用及 `code` 与 `input` 的分离。调用方文档与帮助只写唯一 Node.js 入口，不写安装绝对路径。
- 仅使用可擦除语法：禁止 `enum`、`namespace`、参数属性、装饰器。
- 相对导入必须带 `.ts` 扩展名；类型导入必须使用 `import type`。
- 除官方格式库外零运行时第三方依赖；官方库必须经 `createRequire` 锚点解析后动态 `import()` 加载，禁止静态导入外部包（tsc 无法解析）。
- 导出函数必须显式标注参数与返回类型；禁止 `any` 与非空断言 `!`。
- 错误处理使用 Result 风格（`{success:true,data}|{success:false,error}`）；禁止空 catch；禁止 catch 后静默切换备选路径。
- 文件编码 UTF-8 无 BOM；换行 LF。

## 数据契约

- 会话日志只读；逻辑解码的唯一实现为官方 `@deepseek-ai/dsh-session-format-catalog` 公开 API（`readHeader`/`createRestore`/`decodeRow`/`finish`），全部调用收敛于 `scripts\lib\decode.ts`。只支持当前会话日志格式，不做任何历史日志迁移；低版本日志的 header 分类不是 `current`（`unsupported` 或 `migration-required`）：单目标命令按 `数据不可读` 显式失败，`check` 记为异常并以退出码 3 结束，聚合命令把它列入覆盖声明的排除项。日志格式版本与内容层的交接形态不是同一件事，不得混为一谈。
- 物理层按官方算法（结构性帧扫描）自研；禁止依赖未文档化细节。
- 解码选项固定为 `{ recovery: 'recoverable', validation: 'transformed' }`。
- 物理 JSON 行数与解码得到的事件数分别记录，坏行单独计数；禁止用两者数量相等判断完整性，逻辑结构由官方恢复器的 `decodeRow` 与 `finish()` 校验，异常按数据错误处理（退出 3）。
- 普通 `tool/call` 的 `arguments` 是 JSON 字符串，`tool/result` 的结果取 `data.message`。PTC 的 `tool/ptc-dispatch-start` 参数是 JSON 值，`tool/ptc-dispatch` 的结果取 `data.content` 与 `data.isError`，调用关系由 `rootCallId`、`parentCallId`、`subCallId` 表达。两种事件必须采用一致的工具、问答、子代理呈现与检索语义；错误态依据各自真实字段，不分析 `Error` 正文。
- JSON 的 PTC 条目保留真实事件类型与调用关系，`role` 为 `tool`，`callId` 取 `subCallId`，参数输出规范 JSON 文本；JSONL 保留逐事件原始内容。Markdown 的 `--headers` 为 PTC 条目显示调用与父调用标识。正文只提取文字，JSONL 保留图片块和引用，不读取附件、不执行 OCR、不展示图片本体。
- 不输出工具调用次数、轮次数、步数、消息数、问答数与令牌数量等活动统计，包含 Markdown、JSON 和终端摘要。`hasToolCalls` 只表示是否包含工具调用，Markdown 显示“包含工具调用：是/否”。`list` 排序仅接受 `time`、`created`、`title`、`size`；`stats` 是会话概况；投影元数据不要求 `sessionStats` 与 `tokenUsage` 行。保留轮次大纲、`turns` 内容数组、助手消息的工具调用内容数组、坐标、范围筛选，以及读取规模、检索、覆盖、完整性和子代理节点的数量。
- `readHeader` 分类不是 `current` 时必须显式失败（含 `malformed`、`unsupported` 与 `migration-required`）；禁止回退或猜测。
- 坏行与尾部截断必须记入 anomalies 并在输出中显式标注；禁止静默丢弃。尾部不完整帧整体丢弃并在产物中标注 `尾部未完整帧已丢弃（v1 不做前缀抢救）`，括号内的 `v1` 指前缀抢救策略的版本，与会话日志格式版本无关；`check` 侧另标注 `tornStart` 偏移。
- 会话文件选取：同一会话目录内多代日志并存时取最高版本，同版本优先 `.zstd`。会话发现读 header 走轻量路径（按块增长读取，初始 64 KiB、逐次翻倍，上限为文件大小，只解压第一个完整帧）；完整解码解压全部帧；读取路径任一帧失败即 `数据不可读`，`check` 的结构扫描逐帧记入异常详情而不中止。
- 列表/统计元数据以 projcache 为唯一来源，使用前校验其 `version`（必须恰为 projcache 记录版本 7，与会话日志的格式版本是两套独立版本号，不得混称，后者当前取值见 `tests\fixtures.ts` 的 `CURRENT_LOG_VERSION`）与 identity 可比字段（formatVersion/createdAt/cwd/isSeeded，四项须全等）；校验失败或记录缺失必须标注"元数据不可用"并给出原因，禁止静默空值与跨源混用。**已知边界**：官方写入端接受一组兼容旧版本，本技能刻意只接受严格等值：版本不符时宁可声明不可用，也不按旧结构解释新行；该常量随投影缓存升版必须同步更新，不得为了让元数据"看起来可用"而放宽为区间匹配。
- `show` 直接解码日志，不依赖 projcache；`search` 解码日志，但范围过滤的基准（`lastPromptAt`）与命中分布的标题来自 projcache；工作区标题仅来自 `workspace.json`。`agentPreset` 有两个来源：`list` 的字段取投影缓存，`show` 头部的 `- 预设：` 取日志 header；两者对同一会话可能给出不同取值，这是数据源差异而不是读取缺陷，判定以 `show` 头部为准，`list` 的值只作筛选线索。
- `search --scope` 三档为单调包含关系且 `all` 为穷尽档：`text`=用户/助手正文 ＋ 问答的可读文本（单元名 `提问` 与 `回答`）＋ 合成上下文消息的可读文本（单元名 `上下文摘要`、`交接通知`、`交接指令`、`子代理任务`）＋ 子代理交互的可读正文（单元名 `子代理任务` 覆盖 `subagent` 与 `subagent_fork` 的 `arguments.prompt`，单元名 `发往子代理` 覆盖 `send_message` 的 `arguments.message`；父会话中的这类调用与子代理会话自身的首条任务消息都在本档），抽取规则分别见提问与回答契约、合成上下文消息契约与默认参数注入过滤契约，且与 `show` 默认参数**同一可见性**（框架与插件注入的消息、子代理调度回执都不进本档）；`tools`=另含工具参数与结果（含问答的原始载荷；这三类调用的原始实参在 `tools` 与 `all` 两档可检索；同样排除框架注入与调度回执）；`all`=另含推理/系统/压缩/命令/标题请求/web 请求/交付物/待办/代理信箱 ＋ **每个事件的完整 JSON 载荷**（标签取事件类型），它同时是取回被默认排除内容的入口，因此不做可见性过滤。`all` 档的穷尽性是"检索 0 命中 ⇒ 不存在"这一推断成立的前提，禁止在 `all` 档下遗漏任何事件记录；该穷尽性不得以任何兜底静默降级（例如序列化失败时返回空串把该事件从检索集合中悄悄移除），异常必须显性暴露并由 CLI 顶层映射为 `内部错误`。穷尽性针对**事件记录**而非原文逐字形态：载荷单元是 `JSON.stringify` 的结果，字段值中的 `"`、反斜杠与制表符呈转义形态，因此该推断只对"按记录形态出现"的关键词成立；需要逐字核对原文时用 `show --format jsonl` 导出原始事件行。默认档为 `text`，其覆盖面以本条款为准：问答与三类子代理交互的可读文本因此进入所有默认调用的命中集，这是已批准的对外行为变更。**交接条目不产生检索单元**：`**交接**` 只含结构元数据（轮次、替换区间、前置助手消息坐标与通知坐标），不含交流内容，前置助手消息与通知各由 `assistant` 与 `交接通知` 单元覆盖；为结构元数据另建单元只会让固定词与数字参与命中并放大命中总数。`all` 档仍含 `developer/message` 与 `agent/inbox/spliced` 的完整载荷。命中总数按**检索单元**计数：同一段文本在 `all` 档可能同时命中按字段枚举的单元与整条事件载荷单元而被计两次，因此 `tools`/`all` 的计数大于文本出现次数；`totalIsExact` 仅表示该数未被 `--limit` 截断，不得据此宣称"文本出现次数"。
- 普通工具结果在 `data.error` 存在或 `data.message.isError === true` 时为错误态；PTC 结果在 `data.isError === true` 时为错误态。Markdown 错误标签、JSON 的 `isError` 与问答处理必须遵循各事件的字段，不依据结果正文判断。
- **桌面安装不发运 `.d.ts`**：`app.asar` 内的 `@deepseek-ai` 作用域没有这类文件；同期还有 `.js`、`.cjs`、`.mjs` 与少量 `.ts` 源码（形如 `<包>\src\*.ts`），但那不是声明文件。类型文本由各包 `lib\typert.host.js` 的 `declaration` 字段承载，`MessageSourceMap` 即位于 `dsh-llm\lib\typert.host.js`，并在多个包里逐字重复。因此**禁止把 `.d.ts` 当成可核对的证据源**：任何从 `.d.ts` 核对类型的注释或文档都不成立，只能核对 `.js` 的运行时行为、`declaration` 字段，或官方 npm 包（并在文档里注明该出处只能从 npm 包核对）。
- **会话目录名恒等于日志 header 的 `id`**。目录名有两种形态：裸 UUID 与 `session-` 前缀。但**前缀不能反推会话类型**：既有带 `session-` 前缀却是 `origin: subagent` 的会话，也有带前缀、`origin` 缺失、`parentSession` 存在、`isSeeded: true`、`delegationDepth: 0` 的会话。会话类型的唯一判据是 header 的 `origin`，`--origin` 的 `main`/`subagent` 只看该字段，不看 `parentSession`。header 不可读时按目录名做前缀匹配，这一口径在两种形态下都成立。
- **普通分叉（fork）与 `parentSession`**：当前普通分叉省略 `parentSession`；历史记录可能保留来源 ID。两项都只是历史与当期字段形态，**都不能用来判定类型**：会话类型只看 header 的 `origin`，`origin` 缺失即按主会话处理。子树读取（`show --subagents`、`--session`、`--exclude-session`）沿**实际的** `parentSession` 递归，禁止按目录名、标题或 `isSeeded` 猜测父子关系；因此省略了 `parentSession` 的普通分叉不会出现在任何父子树里，这不是缺陷，也不影响它的类型判定。**禁止据 `parentSession` 存在就把 `origin` 缺失的会话改判为子代理，也禁止假定普通分叉必然带 `parentSession` 或必然出现在父子树中。**
- **`image/offload` 是图片卸载事件**：`data` 只含 `targets`（元素为 `seq` 与 `imageIndexes`），不承载可读正文。技能按普通框架事件处理：默认隐藏，`--events` 显示，`search --scope all` 可检索整条载荷，不据此重放或还原图片，也不改变正文可读性。**工具结果里的 `image` 内容块同样不产生正文**：`toolResultText` 只累加有非空 `text` 字段的块，图片块被跳过，这是刻意的（图片没有可读文本），不是遗漏。

## 标题归一化契约

本节规定会话标题的可用性判定，是标题在全技能范围内的单一真值源；实现必须落在 `scripts\lib\deployment-text.ts` 的 `normalizeSessionTitle`，`scripts\lib\store-metadata.ts`（projcache 来源）与 `scripts\lib\render-core.ts`（`session/title` 事件来源）都必须调用它，渲染层、过滤层与统计层只消费归一化结果。

- 唯一判据：归一化先去掉首尾空白；空标题收敛为 `null`；标题以部署标记起点开头即不可用，判据是起点标签后紧跟一个空格：`<dsh-injection`、`<dsh-message`、`<dsh-result`；第四类是不带空格的起点 `<compacted-summary>`。这是形态判据，不做正文匹配、不按会话类型或预设名分支。
- 两个来源：`list`、`stats` 与 `search` 命中分布的标题取自 projcache 的 `title` 行，`show` 取自会话日志的最后一个非空 `session/title` 事件；两者在读出后立即归一化，消费方不得各自判定。
- 呈现：按本判据不可用时 md 为 `-`、json 为 `null`；不产生任何 `元数据不完整` 声明，元数据可用性判定不受影响。
- 消费面：`--title` 过滤、标题排序，以及 `list`、`show`、`stats` 与 `search` 命中分布的标题呈现都使用归一化结果；禁止在渲染器、过滤层、检索层或统计层重写判据。
- 幂等：同一标题重复归一化必须得到相同结果。

## 部署包装解析契约

本节规定部署侧边界标记的形态与剥离规则，是这类内容在全技能范围内的单一真值源；实现必须落在 `scripts\lib\deployment-text.ts`，正文抽取的出口为 `decode.ts` 的 `userMessageText`、`messageTextFromBlocks` 与 `toolResultText`；正文中被引用的子代理发言由同一模块的 `stripNestedMessageMarkers` 清理。任何渲染面与检索面禁止自行截取或另写形态判据。

- 标记种类与来源：`<dsh-injection …>…</dsh-injection>` 包裹用户角色注入消息（自定义模式部署插件所加；子代理会话的首条任务消息是两个顺序排列的信封；自定义交接的维护指令与压缩通知各是一个注入信封，`kind` 分别为 `handoff-instruction` 与 `context-compacted`）；`<dsh-message role="…" …>…</dsh-message>` 包裹真实用户消息与带文本块的 assistant 消息（同一部署插件的消息时间标记，纯工具调用的 assistant 消息不包裹）；`<dsh-result …>…</dsh-result>` 包裹普通工具结果；`<compacted-summary>…</compacted-summary>` 是标准模式压缩检查点正文里的标签块，不是投递信封。标记由部署侧写入，本技能只解析与剥离，不生成。
- 转义规则：写入侧把正文里的终点字面量转义为 `<\/…>`，因此"第一个未转义的终点"就是真实终点。剥离时禁止反转义，因为该形态在 JSON 字符串内是合法转义，反转义会改坏正文本身含反斜杠的正规载荷。
- 完整信封判据只有三条且缺一不可：以起点前缀加一个空格开头、起点行在首个换行处结束且该行以 `>` 收尾、终点前有一个换行且终点之后紧接文本结尾或另一个换行。第三条的第二半使两个信封可以顺序排列；起点行必须以 `>` 收尾这一条不可省略，否则 `<dsh-injection …>正文` 这种把正文写进起点行的形态会被当成空正文信封，正文被静默丢弃。注入信封、消息信封与工具结果信封共用同一组判据，只有起点前缀与终点字面量不同。
- 剥离只认完整信封：注入信封允许连续出现多个（全部剥离后内层正文以一个换行连接）；消息信封最多一个，且它是真实用户消息或 assistant 消息的最外层；任一信封不完整、或全部剥离后仍有非空残余、或终点后直接紧跟其它内容时，一律**原样返回整个输入**，禁止尽力截取，因为半截信封下截出的任何内容都不再等于被记录的那份正文。内层引用标记是确定的写入形态而非残缺，按各自判据处理，不反转义，也不改动内层正文的任何字符。
- 内层引用标记清理（第二类判据，区别于完整信封剥离）：正文中被引用的子代理发言可能带着 `<dsh-message …>` 起点行与 `<\/dsh-message>` 终点行，后者是外层包裹对终点转义的结果。当且仅当起点行去掉首尾空白后以消息起点前缀开头并以 `>` 收尾、终点行去掉首尾空白后恰好是转义终点时，删除这两行，两行之间的正文逐字保留；找不到成对的终点、任一方不是独占一行、终点未转义、或标记混在行内时，整段原样返回。多个成对按出现顺序逐个处理；该清理幂等，重复执行不产生变化。它不处理完整 `<dsh-message>…</dsh-message>` 信封（那由消息信封剥离负责），也不反转义。
- 严格版与宽松版的分工：工具结果有两个入口。问答载荷解析用严格版（不以起点前缀开头时按原正文返回，以起点开头但信封不完整时返回 `null`），因为 JSON 解析必须区分"裸正文"与"半截信封"，解析不出来就按载荷异常整体失败；展示面与检索面用宽松版（完整即剥离，否则原样返回），因为展示不依赖信封结构，原样显示比丢弃或猜测更诚实。消息信封没有严格版，它不承载需要解析的结构化载荷，展示面与检索面一律用宽松版。
- 作用面：`show` 的 md 与 json、`search` 的检索单元与命中片段都取剥离后的正文，用户正文、助手正文与工具结果一律适用；`**上下文摘要**` 的正文保留 `<compacted-summary>` 标签；`--format jsonl` 保留原始事件，是逐字核对与取回被剥离标记的唯一入口。剥离是展示层的传输格式解析，不改变可见性判定（见默认参数注入过滤契约），也不改变 json 的条目分类；它与该契约禁止的"凭文本匹配判定可见性"不是同一件事，两者不得混用。
- 单一实现位置：本契约的形态判据与剥离算法只允许出现在 `scripts\lib\deployment-text.ts`；调用方只能是 `decode.ts` 的三个抽取出口、`handoff.ts` 的注入起点类别读取（`leadingInjectionKind`）与 `ask-user.ts` 的问答解析。`leadingInjectionKind` 只读完整起点行的 `kind` 属性，不做正文匹配、不反转义，供合成消息判定使用；它的实现与形态判据同处一个模块。内层引用标记清理的实现是同一模块的 `stripNestedMessageMarkers`，由正文抽取出口统一调用，渲染面与检索面不得各自删除标记行。新增需要剥离的载体时必须复用同一组判据，禁止复制一份形态定义。

## 提问与回答契约

本节规定 `ask_user_question`（工具向用户提问）相关消息的抽取、呈现与检索，是这类内容在全技能范围内的单一真值源；实现必须落在 `scripts\lib\ask-user.ts`，md 渲染与检索单元共用同一函数的产出。

- 判定与配对：普通 `tool/call` 或 PTC `tool/ptc-dispatch-start` 的 `data.name` 为 `ask_user_question` 时为提问；普通调用按 `data.callId` 与 `tool/result` 的 `data.message.toolCallId` 配对，PTC 调用按 `data.subCallId` 与 `tool/ptc-dispatch` 的 `data.subCallId` 配对。工具名与载荷结构由工具实现决定，抽取规则以本节登记的结构为准。
- 默认可见：默认参数（不要求 `--tools`）下，提问与配对回答必须出现在 `show` 的 md 时间线中，标签分别为 `**提问**` 与 `**回答**`；未配对的提问照常呈现，禁止因缺结果而丢弃。配对结果为错误态（判据见数据契约）时不产出 `**回答**` 条目，提问照常呈现；提问被中止或取消是正常产品形态，不是载荷异常。
- 可读文本抽取（呈现、检索单元与测试的唯一真值源）：
  - 提问：普通调用解析 JSON 字符串 `data.arguments`，PTC 调用使用 JSON 值 `data.arguments`，取得 `questions[]` 后按其顺序逐题输出，每题固定为三部分：`[<序号>] <header>（id：<id>）`、`问题：<question>`，以及每个选项一行的 `选项：<label>｜<description>`；无选项时省略选项行。
  - 回答：普通结果解析 `data.message.content` 的文本，PTC 结果解析 `data.content` 的文本，得到 `answers[]`，按其顺序逐条输出，每条固定为 `[<序号>] id：<id>`，其后 `selected` 非空时输出一行 `选择：<label1>、<label2>`，`custom` 为非空字符串时输出一行 `自定义：<custom>`；两者皆无时输出一行 `未作答`。
  - 字段缺失按空值契约显示 `-`；全部文本经既有载体规则隔离，并共用 `--truncate` 口径。
- 边界信封（部署形态，解析前必须剥离）：当期部署的边界插件为普通工具结果添加 `<dsh-result …>` 信封，PTC 子调用结果不添加该信封。抽取前必须用部署包装解析契约的**严格版**处理正文：不以起点前缀开头的正文原样解析；以起点前缀开头但信封不完整、或剥离后为空时一律按载荷异常处理。形态判据与转义规则以该契约为唯一真值源，本节不重复登记。
- 载荷异常（禁止降级）：`data.arguments` 无法解析为 `questions[]` 结构，或**非错误态**的配对结果内容无法解析为 `answers[]` 结构时，禁止原样兜底、禁止猜测补齐、禁止静默丢弃。单目标渲染整体失败：退出 3、stderr 单行 `错误: 数据不可读`、不产出文件。这里的单目标渲染指会渲染时间线副本的 md 形态，即 `show` 的默认时间线以及 `--subagents`、`--tools`、`--probe` 三种扩展（`--probe` 为量出真实字节数会完整渲染一次副本，因此同样抽取问答）；`--summary` 不呈现问答条目，因此不做问答抽取，运行到结构不符的载荷时照常成功。聚合检索（`search` 的各档：三档都含问答可读文本，因此同一会话在三档下都必须被排除）把该会话逐条列入 `coverage.excluded`（原因固定文本 `问答载荷结构不符合预期`）并继续，该会话不同时计入 `M`。`show --format json` 与 `--format jsonl` 不做问答抽取，因此不受本条款影响。
- 开关与过滤：这两类恒出现，不提供关闭开关；不受 `--tools` 控制（因此 `--tools` 打开时同一事件会同时以原始工具条目与问答条目出现，两者是同一事件的两种形态），不受 `--role` 影响（与工具、事件一致），仍受 `--turn`/`--seq` 范围选择与 `--head`/`--tail` 条目截取影响；它们不计入 `已隐藏 N 条工具调用/结果`。`**子代理任务**` 与 `**发往子代理**` 按同一思路处理：恒出现、不受 `--tools` 控制、取代对应调用的原始工具条目（见默认参数注入过滤契约）。
- 检索：默认档 `text` 的检索单元包含上述可读文本，单元名分别为 `提问` 与 `回答`；问答的原始载荷仍只在 `tools` 与 `all` 档中。默认档与 `show` 默认参数同一可见性，完整清单以数据契约的 `--scope` 条为准，本节不另立清单（框架注入与调度回执在默认档同样被排除，见默认参数注入过滤契约）。
- 形态差异：问答标签只作用于 md；`--format json` 的 `messages[]` 保留实际的普通工具或 PTC 事件类型，`--format jsonl` 仍是逐字原文入口，`--summary` 视图不输出问答条目。该差异必须同时登记在 `SKILL.md`。
- 标签词表：标签行恒为 16 个取值，含 `提问`、`回答`、`子代理任务`、`发往子代理`、`交接`、`上下文摘要`、`交接通知`、`交接指令`（`工具结果` 与 `工具结果（错误）` 共用标签名，因此结构门禁只登记 15 个名字）；结构门禁白名单与测试断言必须与本节及合成上下文消息契约登记的标签取值同步。

## 交接契约

本节规定上下文交接（`developer/message` 的 `handoff` 型事件）的判定、呈现与检索边界，是这类内容在全技能范围内的单一真值源；实现必须落在 `scripts\lib\handoff.ts`。

- 判定：事件 `type` 为 `developer/message`、且 `data.message.source.kind` 为 `handoff`。判据只取字段，不做文本匹配；不属于 `handoff` 的 `developer/message`（例如 `tool-registry`）不是交接，仍由 `--events` 按通用事件呈现。
- 识别只依赖各事件自身的来源与标记，以及它们的先后次序，禁止按正文文案判定，也禁止假设落账序列一定包含某个中间事件：维护指令是来源 `handoff`、首块注入起点 `kind` 为 `handoff-instruction` 的用户消息，且位于本次交接事件之前；交接事件是 `handoff` 型的 `developer/message`；压缩通知是来源 `handoff`、首块注入起点 `kind` 为 `context-compacted` 的用户消息，且位于本次交接事件之后。生成阶段的助手输出只是普通 `assistant/message`，判定不需要它的位置与内容。
- 正文归属：**交接内容以交接文件为准**。交接事件与通知都不承载文件全文；技能不读取外部交接文件，也不把紧邻交接事件之前的助手消息视作文件正文。那条消息按普通助手消息呈现为 `**助手**`，通知呈现为 `**交接通知**`，两者内容不同，不存在重复，因此**不存在任何副本抑制**。`**交接**` 条目只有三行结构事实，不承载任何正文，也不渲染交接事件自身的载荷。日志中与该交接相关的工具记录可能包含文件内容，因此不得声称日志绝不含正文。
- 压缩通知判定：从交接事件之后按事件顺序扫描，遇到下一条交接事件即停止；遇到 `source.kind === "user"` 的真实用户消息即判为"本轮无通知"并停止，禁止跨轮误认；来源为 `handoff` 且首块注入起点的 `kind` 为 `context-compacted` 的消息即本次交接的通知。判定只读来源字段与注入起点行，不读正文文案。
- 结构事实：条目围栏载荷恒为三行 `轮次 <turn>／步 <step>`、`历史替换 seq <start>-<end>（<n> 条事件）`、`前置助手消息 <locator>；交接通知 <noticeLocator>`；字段缺失按空值契约显示 `-`。`surfaceOp.op` 不是 `replace`、或该字段缺失时，替换区间显示 `-`，禁止把未登记的操作音译成"替换"。
  - `locator` 取紧邻交接事件之前的 `assistant/message`，形态为 `seq N（M 字符）`，`M` 按剥离部署信封后的正文以 Unicode 码点计（与 `--truncate` 同口径）；没有该事件时整个 `locator` 为 `-`。**禁止向前搜索"最近的助手消息"**，那会把更早的普通回答误认成本次交接的前置消息。
  - `noticeLocator` 取已识别的交接通知的 `seq`，形态为 `seq N`；没有通知时为 `-`。它只是坐标，通知正文仍由 `**交接通知**` 条目承载。
- 截断：结构事实行不受 `--truncate` 影响（它是回溯坐标，截断后读不出位置）。该条目没有正文段，因此不存在需要截断的正文。
- 开关与过滤：该条目恒出现、没有关闭开关；不受 `--thinking`/`--tools`/`--events` 控制，且 `--events` 打开时同一事件不得再以通用 `**事件**` 形态出现（一个事件一条条目）；不受 `--role` 影响；仍受 `--turn`/`--seq` 与 `--head`/`--tail` 影响；不计入任何隐藏计数。`--summary` 不输出该条目。
- 检索：不产生检索单元（见数据契约的 `--scope` 条）。前置助手消息的正文由 `assistant` 单元覆盖，通知正文由 `交接通知` 单元覆盖；结构事实是坐标而不是交流内容，另建单元只会让固定词与数字参与命中并放大命中总数。
- 结构字段缺失不是载荷异常：交接结构是元数据，缺失只损失定位精度，不得据此让整条 `show` 失败或让会话被排除出检索结论；这与问答载荷（内容载体，解析不出就呈现不出）的处理不同，两者的边界不得混用。
- 生成指令映射：本模块同时产出生成指令映射（`prompts`），因为判定所需的"交接事件位置"只有本模块掌握；该映射的判定、标签与可见性见合成上下文消息契约。
- 形态差异：合成标签只作用于 md；`--format json` 的 `messages[]` 保留原始事件类型，包括 PTC 子调用事件；`--format jsonl` 仍是逐字原文入口。

## 合成上下文消息契约

本节规定四类合成上下文消息的判定与呈现，是这类内容在全技能范围内的单一真值源；实现必须落在 `scripts\lib\context-checkpoint.ts`（判定与正文抽取），渲染层与检索层只消费它的产出。

合成消息的共同性质：模型可见的消息角色不能替代来源判定，因为框架与插件写入的消息同样会落在 `user` 角色上。判定必须按各类已定义的来源字段与结构识别，禁止按预设名（header 的 `agentPreset`）切换行为，也禁止按正文措辞猜测，因为预设名与部署代际并不同步。

- `**上下文摘要**`：标准模式压缩检查点，`user/message` 且 `source.kind` 为 `compact-checkpoint`，即官方压缩产生的上下文替换形态。其正文前面有一段检查点前言，其后是 `<compacted-summary>` 标签块，两者都必须原样保留，禁止按 `compacted-summary` 判据二次切分。正文经 `userMessageText` 抽取（注入信封与消息信封因此被剥离），不去掉 `<compacted-summary>` 标签本身。自定义交接不产生该条目。
- `**交接通知**`：自定义交接在历史替换后投递的压缩通知，判据见交接契约的压缩通知判定。正文只含压缩告知、交接文件绝对路径与读取要求，不含文件全文，因此不与 `**助手**` 承载的前置消息重复。它不得标成 `**用户**`。
- `**交接指令**`：自定义模式交接的生成提示词。定位方式只有一种，禁止按正文文案判定：从本次交接事件向回扫描到上一个交接事件为止，取最近的一条来源为 `handoff`、首块注入起点 `kind` 为 `handoff-instruction`、且不带 `rpcId` 的用户消息。生成阶段的模型会调用工具，最终回复与维护指令之间隔着多步往返与后续步骤，因此**不能只看前一条事件**；扫描在遇到上一个交接事件时停止，不会把上一次交接的指令认成本次。带 `rpcId` 的是客户端提交的真实用户输入，不得改标。
- `**子代理任务**`：子代理会话自身的首条任务消息。判据：header 的 `origin` 为 `subagent`，且首条 `source.kind === "user"` 的 `user/message` 不带 `rpcId`；遇到首条带 `rpcId` 的用户消息即停止判定，禁止向后继续寻找。主会话不适用。该消息里的回报指引随正文一起呈现，因为标准模式与自定义会话都没有可用于切分它的稳定字段，禁止为此做文本切分。父会话中 `subagent`、`subagent_fork` 两种创建工具调用产生的任务条目复用同一标签名（见默认参数注入过滤契约），两者不冲突：前者是会话首条任务，后者是调用实参。
- 可见性：四者恒默认可见、没有关闭开关；不受 `--thinking`/`--tools`/`--events` 三个开关与 `--role` 控制，不计入任何隐藏计数；仍受 `--turn`/`--seq` 与 `--head`/`--tail` 影响。理由：它们是上下文结构而不是对话双方之一，三个开关的语义是"隐藏框架事件与工具细节"，不适用于已由专门标签承载的结构条目。
- 来源标注：四者的标签已表达真实来源，标签行不得再追加 `来源 …` 标注。
- `--summary` 与 json 的 `turns`：摘要正文、交接通知与生成指令不是用户提问，必须跳过（`checkpointSeqsOf` 产出 seq 集合供 `computeTurns` 使用），使该轮的下一条真实用户消息成为 prompt；子代理任务不跳过，它就是该轮的任务来源。交接通知的来源 `handoff` 已在默认可见白名单内，若不跳过它会成为轮次大纲的 prompt。
- json 分类：四者都仍是 `user/message`，`messages[]` 不新增条目类型。自定义交接的通知与维护指令因此作为普通 `user/message` 出现，正文已剥离注入信封。
- 检索：四者在 `text` 与 `tools` 档各建一个单元，单元名即标签名；`all` 档照常含整条事件载荷。
- 未验证边界：本机真实库只有一次失败的 compaction 尝试，没有成功的 `compact-checkpoint` 样本；该形态的判据来自官方源码与合成夹具，改动本契约时必须先补齐标准模式的成功样本或明确声明该边界，禁止把未验证形态写成已实测。交接通知与维护指令有真实日志样本（生成阶段跨多步工具往返），其判定已按真实形态核对。

## 默认参数注入过滤契约

本节规定默认参数（不传 `--thinking`/`--tools`/`--events`）下哪些消息进入产物，是全技能范围内的单一真值源；实现必须落在 `scripts\lib\visibility.ts`，渲染层与检索层共用同一份判定。

- 判据只允许字段：`user/message` 的 `data.source.kind`、事件 type、普通工具与 PTC 子调用的名称及调用标识。禁止任何文本匹配（标签、注入标记、正文文案都不行）：`<dsh-injection …>` 由多种注入共用，`<dsh-result …>` 只出现在工具结果上，`<system-reminder>` 也可能出现在用户本人输入里，凭标记或正文判定会误判。
- 保留名单是**白名单**：`user`、`compact-checkpoint`、`handoff`、`subagent-settled`、`agent-message`、`user-question-reply` 六种来源默认保留，其余一律排除，含来源缺失、空串与非字符串（无法证明来源，默认不显示）。白名单的失效方向是"新来源种类默认不显示"，属安全方向；黑名单必然漏掉框架与插件未来新增的注入种类。其中 `compact-checkpoint` 是标准模式官方压缩检查点的来源，保留在名单内只表示它不被判为注入；它由渲染层呈现为 `**上下文摘要**`（见合成上下文消息契约），不显示成 `**用户**`。`handoff` 是自定义模式交接的协议消息来源：维护指令与压缩通知都由合成条目呈现为 `**交接指令**` 与 `**交接通知**`，保留它只为让这两类条目能在可见性过滤前被识别，它们同样不显示成 `**用户**`。
- `user-question-reply` 必须留在保留名单内：它是用户对提问的延迟回答，内容与当场答复的工具结果同格式（`{ answers: [{ id, selected, custom }] }`）。提问在等待中被中止、取消或超时时没有配对结果，此时本技能不产出 `**回答**` 条目，该消息是答案的唯一记录；若把它排除，用户的真实回答会在默认产物中彻底不可见。配对结果同时存在时同一答案会出现两次，这是可接受的代价，重复优于丢失。
- 另两类默认排除：`subagent` 与 `subagent_fork` 调用的创建回执，以及 `subagent/catalog` 登记事件。普通调用按 `callId` 与结果的 `toolCallId` 配对，PTC 调用的 `tool/ptc-dispatch-start` 与 `tool/ptc-dispatch` 按 `subCallId` 配对；禁止按 `started subagent` 文案识别。`send_message` 的结果不属于创建回执，不得并入该类计数。
- 必须保留的既有能力不受影响：提问与回答条目（`ask_user_question`）恒默认可见、不受 `--tools` 与 `--role` 控制、仍受范围选择影响、不计入工具隐藏计数（见提问与回答契约）；交接条目（`developer/message` 的 `handoff` 型）与四类合成上下文消息（`上下文摘要`、`交接通知`、`交接指令`、`子代理任务`）恒默认可见、不受三个开关与 `--role` 控制、不计入隐藏计数（见交接契约、合成上下文消息契约）；用户本人消息、助手正文、子代理结算与中途发言照常保留。
- 新增可见项：`subagent` 与 `subagent_fork` 调用呈现 `**子代理任务**（<description>）` ＋ `arguments.prompt`，`send_message` 调用呈现 `**发往子代理**（<子代理 id>）` ＋ `arguments.message`；三者取代对应调用的原始工具条目（同一调用只呈现一次），因此不受 `--tools` 控制。父会话中的调用正文与子代理会话自身的首条任务正文都纳入默认 `text` 检索；后者仍按子代理任务消息规则呈现。调度参数（`provider`、`model`、`reasoning_effort`、`run_in_background`）不进默认产物。完整调用实参可用 `show --format jsonl` 核对，也可在 `search --scope tools` 或 `all` 中检索。`arguments` 解析失败时不得兜底转储，按普通工具调用处理（`--tools` 可看到原始实参），异常因此仍可定位。
- 单一实现归属：子代理调用的可读正文由 `context-checkpoint.ts` 统一提取，展示与检索复用同一结果；创建工具名与回执判定由 `visibility.ts` 统一维护。
- 排除必须计数并声明：`show` 的摘要行给出 `已排除 N 条框架注入（--events 显示）` 与 `已排除 M 条子代理调度回执（--tools 显示）`（两类分开，不得合并成一条）；`search` 在 `text` 与 `tools` 档给出 `已排除 N 条框架注入与 M 条子代理调度回执（--scope all 可检索）`。不声明会让调用方把"被默认排除"读成"不存在"。
- 取回入口：`--events` 恢复注入消息、`--tools` 恢复调度回执与其它工具结果、`search --scope all` 恢复被排除内容的检索、`show --format jsonl` 逐事件穷尽（不做任何可见性过滤，是唯一不受过滤影响的形态）。
- 口径统一：`show` 的 md 时间线、`show --format json` 的 `messages`、`search` 的 `text` 档三处必须给出同一可见性；`--probe` 按同一组开关渲染副本，字节数随之自然变化。
- 计数与呈现必须用同一判据：被跳过的事件在渲染循环内计数并 `continue`，禁止在渲染函数内另设计数分支（`--head`/`--tail` 截断会让计数与实物脱节）。
- 覆盖声明不受影响，排除的是消息而不是会话，`N`/`M`/`K` 的定义不变。

## CLI 契约

- 子命令固定为 `list`、`show`、`search`、`stats`、`check`；每个命令只接受自己的选项集，未知或不适用选项退出 2。
- 全局选项固定为 `--dsh-home`、`--lib-root`、`--output-dir`、`--name`、`--format`、`-h/--help`。
- `--dsh-home` 只选数据根（`sessions` 与投影缓存所在），与官方格式库的版本、位置**无耦合**：库恒为桌面版安装内那一份（或 `--lib-root` 显式覆盖的那一份），实现上 `defaultLibRoot()` 也不接收 `dsh-home`。指向另一份会话数据时两边的版本各随其安装，错配不会静默兜底，只会以解码失败（聚合命令逐条列入覆盖声明的排除项、单目标命令退出 3）暴露。
- `--format` 取值：`md`（默认）/`json`；`show` 额外支持 `jsonl`。呈现类开关（`--role`、`--thinking`、`--tools`、`--events`、`--headers`、`--truncate`、`--turn`、`--seq`、`--head`、`--tail`、`--probe`）仅 md；`--summary` 与 `--subagents`（内容范围开关）在 jsonl 禁止（违者退出 2）。`--head` 与 `--tail` 互斥；`--summary` 与 `--turn`/`--seq`/`--head`/`--tail` 互斥；`--probe` 与 `--subagents` 互斥（`--probe` **允许**与其它呈现类开关同用：它按同一组开关渲染副本并据实报告字节数，这正是"量出带这些选项的导出有多大"的用法）。旧取值 `text` 已移除，传入即退出 2。
- `--full` 是 `list` 专有的呈现类开关，只改变 md 形态（逐会话块替代精简表格）：与 `--format json` 同用时被接受但无效果，既不退出 2，也不改变 json 产物。帮助文本与 `SKILL.md` 必须按"被接受但无效果"描述，不得写成"只支持 md"，否则会让调用方以为该组合属选项组合违规。
- 取值语义：`--limit`、`--head`、`--tail` 的 `0` 表示不限；`--truncate` 的 `0` 表示不截断；`--context` 默认 60 且按码点取命中两侧窗口；`--turn` 最小 1、`--seq` 最小 0，区间含端点。
- 解析语义：选项不可重复（重复即退出 2）；开关不接受值（`--full=1` 退出 2）；支持 `--opt=value` 内联写法；位置参数不终止选项解析；不存在 POSIX 合并短选项；`-h`/`--help` 出现在终止符之前即短路为帮助，帮助写 stdout、退出 0、不要求 `--output-dir`；总帮助与各子命令帮助的用法行均写 `node "<skill_dir>/scripts/run-session-reader.ts"`，`<skill_dir>` 是技能目录的绝对路径占位符。
- `--name` 只接受单一路径段：ASCII 字母、数字、`_`、`-`，加全部汉字（Unicode `Script=Han`，含扩展 B 及以后，如 `𠮷`）；长度 1-64（按 UTF-16 单元）；拒绝 `.`、路径分隔符、空白、控制字符与 Windows 保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`-`COM9`、`LPT1`-`LPT9`，共 22 个）。理由：产物路径必须恒为 `--output-dir` 的直接子文件。汉字白名单必须用 `Script=Han` 属性表达，禁止改写为手写 `\uXXXX` 区间，因为手写区间只覆盖基本平面，会把扩展平面的正常汉字误判为非法，与"中文可用"的对外承诺矛盾。
- 支持 `--` 选项终止符：其后所有 token（含以 `-` 开头者）一律作为位置参数；帮助识别只扫描终止符之前的 token。必需选项必须写在终止符之前。`--output-dir` 落在终止符之后时，接受位置参数的子命令（`show`、`search`、`stats`、`check`）报 `位置参数过多`，`list` 报 `该命令不接受位置参数`。帮助文本与 `SKILL.md` 必须同步登记。
- 范围过滤（`--workspace`、`--since`、`--until`、`--origin`）仅作用于 `list`/`search` 与 `stats` 的全局聚合；`stats <目标>` 提供目标时与范围过滤同用即拒绝（退出 2），不做静默忽略。`search --session <标识>` 与 `search --exclude-session <标识>` 复用 `show` 目标语法，作用为该会话及其 `parentSession` 递归子树的正选与反选，与范围过滤以交集生效；两者可同时给出，此时对同一子树取交集（通常得空集）；目标不存在时按目标解析三态报错（不静默忽略）。
- 过滤项的失败与匹配语义必须区分：`--workspace` 为路径归一化全等（`\` 转 `/`、去尾部 `/`、转小写）或工作区标题全等，无任何匹配时按 `target-missing` 退出 1；`--title` 为标题子串匹配、不区分大小写，标题归一化后不可用或元数据不可用时该会话落选，无匹配时正常返回空结果、退出 0；`--origin` 的唯一判据是 header 的 `origin` 为 `subagent`，**不看** `parentSession` 是否存在（`origin` 缺失即按主会话处理，无论该会话是否带 `parentSession`）。
- `search` 与 `stats` 恒包含空会话（`includeBlank: true`），`list` 默认隐藏 `blank` 为真者且只提供 `--include-blank`；`blank` 为 null（元数据不可用）不隐藏。
- 选项表是解析、校验与帮助的单一真值源；修改 CLI 必须同步更新选项表、帮助文本、`SKILL.md` 与测试。
- 退出码：`0` 成功（含 0 命中等空结果、`--help`、`check` 无异常）；`1` 目标不存在（含前缀歧义、`--workspace` 无匹配、`--dsh-home` 不存在、`sessions` 缺失）；`2` 参数错误（含未给 `--name` 时目标已存在、前缀短于 8 字符）；`3` 数据/IO 错误（含官方格式库加载失败，其分类为 `内部错误`；以及问答载荷结构不符合预期，其分类为 `数据不可读`）。`check` 发现异常时**先落盘并打印两行 stdout、stderr 为空，再以 3 结束**，因此非 0 退出不蕴含没有产物。
- stderr 只输出单行 `错误: <分类>`；分类全集：`参数无效`、`目标不存在`、`输出文件已存在`、`输出目录创建失败`、`输出写入失败`、`输出移动失败`、`数据不可读`、`内部错误`。分类后可附一段括号说明：歧义目标附候选数（形如 `错误: 目标不存在（候选 N 个）`）；**仅组合冲突分支**附冲突选项名与**可执行的合法替代写法**（形如 `去掉 --events，或把 --format 改为 md`），替代写法用分号分隔、禁止嵌套括号；解析层与取值诊断分支只回显选项名/子命令位 token 或合法格式，不提供替代写法。说明来源固定为四类：`validateCommandOptions` 的组合约束、解析层 `parseCommandLine` 的错误文本（只回显选项名、子命令位 token 或位置参数占位名，不回显选项值）、固定模板的取值诊断（`--name`/`--turn`/`--seq`/`--since`/`--until`，只含选项名与合法格式，不含调用方数据；**唯一例外**是 `--name` 的 Windows 保留设备名分支，它回显命中的保留设备名（大写形式，判定不区分大小写，因此传入 `con` 时回显 `CON`）以便定位）、以及官方格式库定位与加载失败这一固定模板（只写失败阶段与可执行的下一步，不回显实际取值）。错误行不得包含会话内容、会话 ID、用户名、dsh 数据路径与安装绝对路径（默认锚点与 `--lib-root` 的实际取值都算，锚点只以 `%LOCALAPPDATA%` 占位形态出现）；数据层 `StoreError.detail`（含会话目录名与绝对路径）禁止外显，仅 `argument-invalid` 的固定模板 detail 可由 `mapStoreError` 透传。临时文件清理失败并入当次失败分类：写入阶段的清理失败固定报 `输出写入失败（临时文件未清理）`，移动阶段的清理失败固定报 `输出移动失败（临时文件未清理）`，说明不含任何路径。
- 目标解析必须三态可区分：唯一匹配且可读 → 执行；多个匹配（含 `session-` 前缀归一化后的精确歧义与一般前缀歧义）→ `ambiguous`/退出 1；无匹配但存在因 header 不可读而被跳过的会话目录其标识前缀匹配 → `data-unreadable`/退出 3；其余无匹配 → `target-missing`/退出 1。被跳过目录的匹配按目录名判定（header 不可读时无从取得逻辑 id）。**标识匹配接受带 `session-` 前缀与裸 UUID 两种写法**（调用方从产物拿到的 id 带前缀，从目录名或事件字段摘出的不带），这只是取值来源不同，不用于推断会话类型；会话类型只看 header 的 `origin`。
- 时间显示为含时区偏移的 ISO 8601 本地时间（秒级、无毫秒）；JSON 中的时间字段为原始毫秒数。过滤参数按 UTC 解析：接受毫秒数或严格 ISO，纯数字串按毫秒解释，无时区后缀按 UTC，日历或偏移越界即拒绝。
- 过滤基准是会话的"有效最近活动时间" = projcache 的 `lastPromptAt`，缺失时回落 header `createdAt`；比较双端含端点，不校验两者先后。它与产物中的 `事件时间范围`（来自事件自带 `time`）不是同一口径，两者不得互相替代。
- 空值在文本中显示 `-`，在 JSON 中为 `null`。

## 覆盖声明契约

- 每个命令的产物（md 与 json）必须让调用方判定“扫到了什么、纳入了什么、排除了什么、是否被截断”，字段与文案固定（`--probe` 产物按“规模探测”条款只含头部与预计字节数，不含覆盖声明）：
  - md：`扫描会话 N 个；纳入 M 个；排除 K 个`，随后对每个被排除会话输出一行 `排除会话：<完整 id>（<原因>）`；`show --subagents` 另对每个归属未知的跳过项输出一行 `归属未知：<id>（<原因>）`；`search` 与 `stats` 另输出 `扫描明细：解码日志 X 份；读到事件 Y 个；解码失败 Z 份；帧解压失败 W 帧` 与 `事件时间范围：<下界> ~ <上界>`；`search` 另输出 `命中总数：X`（被截断时追加 `；已截断显示 N 条（--limit 0 显示全部）`）、`检索范围：<scope>（<覆盖面描述>）；命中总数 X 为精确值`（顺序为先 `命中总数` 后 `检索范围`）与 `## 每会话命中分布` 表格及其固定提示行；`show` 在范围选择生效时按块输出 `筛选：…；显示 X 条时间线条目（区间内事件 Y 个，共 Z 个事件）`。
  - json：`coverage: { scannedCount, includedCount, excluded: [{ id, reason }], unattributable: [{ id, reason }] }`；`search` 与 `stats` 另含扫描明细，`search` 另含范围与命中分布。
- 覆盖声明的 `M` 与 `K` 按命令分述，禁止用一条统一定义概括全部命令：`list` 描述发现阶段的全库覆盖：`M` 是 header 可读的会话数、`K` 是 header 不可读者，与范围过滤、空会话隐藏、`--limit` 均无关（过滤结果由合计行单独表达）；`search` 与 `stats` 描述本次作用域：`M` 是范围过滤后的会话数减去其中解码失败者，`K` 是发现阶段 header 不可读的全库会话（无从判定其是否符合过滤条件）加作用域内解码失败者；`stats <目标>` 恒为 `{1,1,[]}`；`show` 的 `N = M =` 本目标及其子树的可读节点数（未开启 `--subagents` 时为 1）、`K` 恒为 0（可归属的排除项不存在，无法归属者列入 `unattributable`）；`check` 的 `K` 恒为 0。`N = M + K` 恒成立，且实现即按 `N = M + K` 构造该声明，因此禁止在任何代码注释、文档或文案中把它表述为"调用方据此核对是否存在未列出的漏读"，它不携带超出 `M`、`K` 的信息，核对覆盖范围只能依据逐条列出的排除项。**同一会话不得同时计入 `M` 与 `K`。** `unattributable` 单独计数，不计入 `N`/`M`/`K`。
- 被排除的会话必须逐条列出，禁止合并为计数或静默丢弃。单个会话 header 不可读或解码失败不得使聚合命令（`list`/`search`/`stats`）整体失败，因为那会让一份损坏日志永久阻断对其余会话的浏览与检索；改为跳过并声明。单目标命令（`show`、`stats <目标>`）在目标自身不可读时显式失败（退出 3）；`show --subagents` 在任一子代理解码失败时同样显式失败，而 header 不可读的子代理无从判定归属，必须列入 `unattributable` 而非静默丢弃。
- 覆盖声明描述"本次检查了哪些会话"，与 `--limit` 无关（`--limit` 只决定产物列出多少条，由命令级摘要与产物行数表达）。`includedCount` 不得包含任何已列入 `excluded` 的会话：解码失败的会话只出现在 `excluded` 中。
- 扫描摘要的语义边界：`logsDecoded` 是成功解码的日志份数，`eventsRead` 是解码得到的事件总数，`decodeFailures` 是解码失败的日志份数（逐条在 `coverage.excluded` 中），`frameFailures` 是帧解压失败的帧数累计。`observedFrom`/`observedTo` 来自**事件自带的 `time` 字段**，禁止改用会话的"最近活动时间"（后者来自 projcache，语义不同）。
- `search` 的 `--limit` 只限制 `hits` 收集上限，`totalHits` 对纳入会话全量计数且不做提前终止；`totalIsExact` 恒为 `true`（类型即字面量 `true`，因此渲染层不得保留任何不可达的"下界"分支），其证据链为：全量计数 ＋ `scope=all` 覆盖任意事件记录的完整载荷 ＋ 未纳入会话逐条列入 `coverage.excluded`。该数的计量单位是检索单元内的匹配次数，不是文本出现次数。
- 元数据问题的逐条声明分两种粒度且不得自相矛盾：字段级判定用 `--full` 的 `**元数据**` 字段（`available && reasons.length > 0` → `部分缺失`；`!available` → `不可用`）；逐条声明行用 `元数据不完整：<完整 id>（<原因>）`（`stats <目标>` 为不带 id 的 `元数据不完整：<原因>`），因为触发条件是"存在不可用字段"（`reasons.length > 0`），既覆盖整体不可用、也覆盖可读但缺字段。禁止用 `元数据不可用` 描述后者，否则同一会话会在同一产物里被同时写成"部分缺失"与"不可用"。
- 命中分布（`distribution`）必须包含**0 命中的纳入会话**，按命中数降序、同数按会话 id 升序；其存在理由是让调用方把"自己的会话与子代理会话的命中"从结论中剔除（检索在全库上做，调查笔记与复述过的错误串都会被命中）。表格为空时不得输出该区块（空表会触发 MD055）。
- 调用方剔除自身语料的两种手段必须同时提供：产物中的逐会话分布（人工判断）与 `--exclude-session <标识>`（自动化，语义为该会话及其 `parentSession` 递归子树的反选）。

## 输出策略

- 所有命令必须显式指定 `--output-dir`（无默认值）；缺省退出 2；工具对目录位置零假定、不校验，不限制其是否位于 dsh 主目录内（唯一要求是调用方显式指定）。
- 目录不存在时创建；创建、写入或移动失败退出 3。
- 文件名：未指定 `--name` 时为 `session-reader-<命令>-<UTC 时间戳>-<随机 6 位>.<ext>`（md→md、json→json、jsonl→jsonl），指定 `--name` 时为 `<name>.<ext>`。
- 未指定 `--name` 时目标文件必须不存在；已存在时拒绝且不得改动原文件。实现为先 `existsSync` 检查、再写唯一临时文件、最后同卷 `renameSync`；"绝不覆盖"由命名唯一性（UTC 毫秒时间戳 + 随机 6 位后缀，碰撞概率 36⁻⁶/毫秒）消解，存在性检查与 rename 之间的竞争窗口在命中"同毫秒 + 同后缀"前不可触发（不改代码）。
- 指定 `--name` 时允许原子替换：Windows 的 `renameSync` 走 `MOVEFILE_REPLACE_EXISTING`，任何时刻目标文件要么是旧内容、要么是新内容；覆盖范围严格限于 `<output-dir>/<name>.<ext>`。
- 先写唯一临时文件，关闭后同卷原子移动；失败时必须清理临时文件。临时文件恒为 `.<产物文件名>.<随机 6 位>.tmp`（与目标同目录以保证同卷）。
- 输出编码固定 UTF-8 无 BOM、LF、末尾恰一个换行。
- stdout 固定两行：`完整输出已保存到: <绝对路径>` 与 `<摘要>；输出文件共 N 行`；N 必须等于输出文件实际行数；终端不显示会话正文。命令级摘要（第二行 `；` 之前的部分）必须由 `scripts\lib\render-summary.ts` 唯一产出：md 与 json 两组渲染函数都返回 `{ content, summary }`，CLI 层禁止自行拼接任何摘要文本，同一调用的摘要不得因 `--format` 不同而不同。摘要只描述产物的规模与口径，不得引入产物未支撑的断言（例如 `--subagents` 未开启时不得出现子代理数）。
- md 输出必须真实通过全局 markdownlint 基线（技能根 `.markdownlint.jsonc` 与全局基线逐条一致，只允许更严格）：禁止文件内豁免注释、禁止配置放宽、调用方无需排除输出目录；生成规则见下节"md 输出格式契约"。

## md 输出格式契约

md 渲染遵循 lint-safe 规则（R1 至 R5）；实现与测试的单一真值源为 `scripts\lib\render-core.ts`（载体与工具）、`render-md.ts`（聚合命令 md）、`render-show-md.ts`（show 的 md）、`render-json.ts`（JSON/JSONL）、`render-summary.ts`（命令级摘要文案）、`message-source.ts`（来源归属与来源标注）、`ask-user.ts`（问答的可读文本抽取，md 渲染与检索单元共用）、`handoff.ts`（交接条目的结构事实抽取）、`deployment-text.ts`（部署包装的解析与剥离）与 `context-checkpoint.ts`（合成上下文消息的判定与正文抽取），及其单元测试与 lint 门禁：

- R1 骨架与空白纪律：文件为 UTF-8 无 BOM、LF、末尾恰一个换行；标题/列表/表格/围栏/段落之间恰一个空行；标题仅用 ATX 且行首书写、文本取固定词表、无尾标点、同级唯一；加粗只作行内前缀（标签行恒以 `：` 收尾，禁止独立成段）；列表只用短横线标记且标记后恰一个空格；表格首尾管道齐全、列数一致、单元格间距统一、前后空行；围栏固定为反引号 + 语言 `text`，反引号长度 = 载荷最长连续反引号串 + 1 且不小于 3。
- R2 载体隔离：多行文本只用围栏代码块承载；单行文本只用行内代码跨度承载（反引号长度动态；内容以反引号开头或结尾时双边加一个空格内边距）；表格单元格值先经行内载体再把 `|` 转义为 `\|`；禁止任何会话来源文本以裸文本进入结构。
- 来源标注（受控例外，仅 `user/message` 事件）：`**用户**` 标签只表达模型可见角色，会把子代理中继、结算通知与插件注入显示成"用户写的"，因此凡 `user/message` 且来源不是用户本人，标签行括号内与检索命中行的 `（seq N）` 内必须追加 `来源 <kind>`。`agent-message` 与 `subagent-settled` 追加 `<senderSessionId>` 以便定位是哪个子代理，`plugin` 追加插件名，其余 kind 不加取值，`kind` 缺失、非字符串或空串时为 `来源 未标注`；空串与缺失一律按"无该字段"处理（空串没有信息量，渲染成空载体既不可读也失去标注意义）。kind 在本技能识别的词表内时裸写，词表外的值必须入行内载体原样呈现，因为来源种类是官方与插件共同扩展的合并联合，该词表不是完整声明，禁止丢弃、改写或把未知取值归入最接近的已知类别。**一切取自日志的取值（插件名与会话 id）都必须入行内载体**：日志字段可能含反引号或换行，裸写会把标签行拆成两行并让裸文本进入骨架。标注的判据、词表与载体处理只能由 `scripts\lib\message-source.ts` 产出，md 与 json 两条路径共用同一归属对象（json 形态为 `{ kind, form, senderSessionId, plugin }`，无值者 `null`），禁止任何渲染器自行判别来源。`**助手**`/`**推理**`/`**工具调用**`/`**工具结果**`/`**系统消息**`/`**事件**`/`**提问**`/`**回答**`/`**子代理任务**`/`**发往子代理**`/`**交接**`/`**上下文摘要**`/`**交接通知**`/`**交接指令**` 行、轮次大纲与 `--probe` 不适用该标注（各自标签已表达来源，或条目契约中没有标签行）；轮次大纲与 json `turns` 因此不含来源，这条差异必须写进 `SKILL.md`，不能让调用方在摘要视图里读到来源不明的 prompt 而无从判断。
- R3 极小归一化（唯一允许的内容改动）：CRLF 与孤立 CR → LF；制表符 → 4 空格（MD010）；行内载体首尾空白去除（MD038；全空白值保留原样）；行内载体与轮次大纲把内嵌换行折叠为空格（单行载体的前提，改变字符序列，因此必须显式登记）；当且仅当围栏载荷每个非空行都匹配 `^\s*\$\s+` 时在载荷末尾追加一行单个空格（MD014；原文各行逐字不变）。CR 归一化的必要性：会话正文可能含 CR 字节，此时产物会混入 CR，而 markdownlint 无规则可判 CR，因此它是契约层面的静默破坏而非 lint 问题（计数随门禁规模变化，故不写具体数字）。
- R4 边界：空值显示 `-`；控制字符、RTL/组合字符、零宽字符、NUL 在代码载体内原样保留；超长单行不截断（MD013 关闭）。
- R5 参考实现：规则逐字定义以 `scripts\lib\render-core.ts` 为唯一落地处，行为由 `tests\render-core.test.ts`、`render-list.test.ts`、`render-show-md.test.ts`、`render-show-json.test.ts`、`render-search-stats-check.test.ts`、`render-boundary.test.ts`、`source-annotation.test.ts`、`deployment-text.test.ts`（规则单元测试）与 `tests\lint-matrix.ts`（全组合穷尽门禁）双重覆盖。
- 会话标识输出：列表、命中行与摘要行一律输出**完整会话 id**，禁止输出截断值，因为显示值必须与可传值同源，截断值必然引入"显示≠可用"这一整类缺陷。
- 文本载体截断：所有文本载体（用户/助手正文、推理、工具参数与结果、系统消息、`--events` 事件载荷、轮次大纲、问答的可读文本、`上下文摘要` 正文、`交接通知` 正文、`交接指令` 正文、子代理任务正文）共用同一 `--truncate` 口径，按码点截断并追加 `…`，`0` 即不截断，禁止为任何载体另设固定上限。唯一例外是每会话命中分布表格的标题列（按码点截断 40，见下条）；`**交接**` 的结构事实行属固定词表的元数据，不参与截断（见交接契约）。
- 范围选择的呈现语义：`--turn`/`--seq` 筛选事件序列（交集、含端点）且作用于每个块（子代理各自的 turn 与 seq 按自身事件流计），`--head`/`--tail` 按**条目**（标签行 ＋ 正文载体为一个单位）截取筛选后的序列且只作用于根块；同一事件可以产生多个独立条目，每个标签及其正文分别计数和截取。子代理块因此只受 `--turn`/`--seq` 影响。筛选说明行只列**该块真正生效**的条件：`--head`/`--tail` 不是根块时不得出现，否则会出现"首 N 条；显示 M 条时间线条目（M > N）"这种同句自相矛盾的产物；`显示 X 条时间线条目` 的 `X` 必须是条目数而不是 md 行数。`筛选：` 与 `摘要：` 都是条件输出（无范围选项 / 无隐藏项时不输出）。
- 规模探测（`--probe`）只输出头部和按同一组选项完整渲染得到的预计 UTF-8 字节数，不输出正文、消息数或问答数。头部包含日志绝对路径，须按敏感信息处理。
- 每会话命中分布表格的标题列按码点截断到固定上限，避免单行无界增长。
- 子代理块层级：所有子代理块固定 H2（`## 子代理 <路径编号>`）、子内容固定 H3；嵌套关系只由路径编号表达，标题层级不随深度递进（保持实现不变；按标题层级解析的读者以路径编号判父子）。路径编号的规则必须登记到可实现的程度：各层内按子节点 1 起序号、以 `.` 连接，因此 `1.2` 是根的第 1 个子代理的第 2 个子代理。
- 技能目录的 lint 边界：技能自带 `node_modules`（开发依赖），从技能目录运行 lint 时由技能根 `.markdownlintignore` 排除。技能自有 `.md` 文件必须全部纳入检查，禁止借 ignore 排除自有内容。技能根 `tmp\` 是非交付临时目录，必须同时被技能根 `.markdownlintignore` 与 `biome.json` 的 `files.includes` 排除，因为执行规范要求临时文件写入项目 `tmp\`，若该目录参与 lint 与静态分析，任何临时产物都会让校验链的前两步无故失败（实测：复核者写入的报告与探针脚本会让 `biome ci .` 与 `markdownlint-cli` 双双向非 0 退出）。

## 兼容性要求

- 官方库 API 变化只允许修改 `decode.ts` 单点适配；`--lib-root` 必须始终可覆盖默认锚点。
- **`--lib-root` 的成功覆盖需要一棵依赖闭包完整的 `node_modules`**：锚点判定只查 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-session-format-catalog` 两个包，但那只是「这个目录像不像 dsh 安装树」的判据，不是「库能不能加载」的判据。`dsh-session-format-catalog` 静态 import 了 `dsh-session`、`dsh-session-format` 与四代迁移适配器，`dsh-session` 又 import `@deepseek-ai/cordis`；因此只复制若干包到磁盘后加载会以 `Cannot find package '@deepseek-ai/cordis'` 失败。可复现判据：用桌面载体对目标目录执行一次 `list`，退出 0 即成立。
- 默认锚点由 CLI 按结构定位：在 `%LOCALAPPDATA%\Programs` 的直接子目录中，取 `resources\app.asar\dsh\node_modules` 同时含 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-session-format-catalog` 的那一棵，必须恰好一个；这是**唯一锚点、不带任何回退**，缺少 `%LOCALAPPDATA%`、非 Windows、锚点不成立或候选不唯一即返回 undefined。**禁止在代码、注释、文档与错误文案里写死安装目录名**：写死名称会把任何名称形态差异直接变成定位失败，且该失败形态与真实缺装无法区分。禁止恢复对 npm 缓存 npx 安装树或 `<dsh-home>\profiles\node_modules` 的探测，禁止的理由是**唯一权威位置**，不是"这些目录不存在"：npm 缓存的 `_npx` 安装树可能因某次 `npx dsh` 仍然留在本机（本机实测其中就有一棵含当前版本两包的树），`<dsh-home>\profiles\node_modules` 也已不存在（当前布局是每个 profile 各自的 `<dsh-home>\profiles\<名称>\node_modules`），两者是否在、装的是哪个版本都随本机安装与运行历史漂移，因此都不能保证与桌面版同版，写死或继续探测只会以"官方格式库加载失败"整体失效；也禁止以"找不到就换一个目录"的方式静默降级。锚点不成立或库加载失败必须显式报错退出 3，并在错误说明里给出可执行的下一步（用 `--lib-root` 指定含 `@deepseek-ai` 的 `node_modules` 目录）；错误说明禁止回显安装绝对路径，锚点位置只以 `%LOCALAPPDATA%` 占位形态出现。
- `app.asar` 是 Electron 归档，其虚拟路径由桌面运行时解析。系统 Node.js 24 执行启动入口，业务 CLI 与需要官方库的测试使用桌面运行时。测试夹具若要在磁盘上伪造含 `app.asar` 段的锚点，必须逐级 `mkdirSync`，避免 Electron 对该路径的递归创建报 `ENOTDIR`。
- 测试以子进程驱动 CLI 或门禁时，子进程必须继承 `ELECTRON_RUN_AS_NODE=1`：`process.execPath` 在桌面版宿主下是 Electron 可执行文件，缺少该变量会把 CLI 当桌面应用启动而整体失控（实测表现为成批 CLI 用例失败）。普通 Node 会忽略该变量，故无条件设置是两种宿主下都安全的写法。
- 测试入口写 `--test "tests/**/*.test.ts"`（glob），不要写 `--test tests`（目录形式在桌面版运行时的 Node 线 24.x 上会报 `Cannot find module ...\tests`）。
- 格式版本由官方库 `currentVersion` 决定，产物头部显示 `v<版本>`；代码与**测试**都不得写死具体版本号对应的格式结构假设。夹具写出的日志版本由 `tests\fixtures.ts` 的 `CURRENT_LOG_VERSION` 单一维护，需要文件名版本段或 header `version` 时一律引用它；写死数字会让每次 dsh 升级打红一整批与版本无关的用例（本技能已因此实际失败过一次）。
- 事件行必须满足当前版本的结构约束，夹具据此在 `eventLine()` 内集中规范化，而不是散落在各测试文件：事件必须填写真实 `type`，供按事件类型取字段，禁止省略类型来模拟普通结果；`time` 必须是安全整数（非整数或非有限数会在序列化时变成 `null`，该行随即被解码器判为结构违规并让整份日志解码失败，报错位置离根因很远）；带一级消息对象的事件必须携带字符串 `id`。普通 `tool/result` 的消息是“工具”角色的一级消息，`toolCallId` 与 `isError` 是消息字段而非 content 内嵌字段；PTC 结果遵循数据契约，不要求 `message` 或 `toolCallId`。夹具事件定义与该转换的分工必须保持单一来源。
- 日志的**文本抽取**以当前格式为准：内容块是平铺的 `{type:"text",text}`。旧版嵌套内容块不再支持，低版本日志按 `数据不可读` 显式失败，不做迁移。`textFromBlocks` 只计 `type` 为 `text` 且 `text` 为非空字符串的块，其行为由单元测试锁定。
- 问答的载荷结构由工具实现决定：提问的参数按 `questions[]` 的 `id`/`header`/`question`/`options` 解释，回答的结果按 `answers[]` 的 `id`/`selected`/`custom` 解释，字段结构以提问与回答契约一节登记为准；工具名或结构变化时按载荷异常条款整体失败或列入排除项，禁止静默降级为无内容。工具以错误态结果（判据见数据契约）表示提问被中止或取消，这类结果不是回答载荷，按"没有回答"处理而不是载荷异常。
- 代理预设支持 `standard`、`cordis`（创造模式）、`ptc` 与 `dsh-custom-ptc`。四者使用当前官方格式库，按事件字段处理，不按预设名或会话 id 分支；旧日志不迁移。
- dsh 升级后必须重跑全部测试与真实数据只读抽查，并记录官方库版本。

## 发布要求

本技能以独立仓库发布（GitHub 上的 `dsh-session-reader`），仓库根即技能根，发布内容由上层 dsh 仓库单向派生。技能本体始终在 `~/.dsh` 内开发与维护，发布不改变这一点。

### 形态约束

- **禁止在技能目录内 `git init`**：该目录由上层仓库以普通文件跟踪。在其内建仓库会让上层仓库把该目录记为 gitlink，已跟踪文件当即失去跟踪，从而形成两份互不相干的真值源。
- **禁止 submodule 或 subtree 反向引用**：技能必须同时满足"由上层仓库跟踪"与"是本机可用技能"，反向引用会让每次修改都需要在两个仓库之间对齐提交。

### 派生、清理与推送

- 派生：`git subtree split --prefix=skills/session-reader` 取技能目录的提交链。
- 清理：对派生链做去标识化，并把提交身份统一为 GitHub 的 noreply 地址。
- 推送：`git -c credential.helper=… push <完整远程 URL> <分支>:main`。

三条硬性要求：

- **派生与清理必须是输入的确定性函数**：同一条命令重跑两次必须得到相同的提交哈希链。满足该判据时，上层仓库追加新提交后重新派生与清理的结果以既有发布链为前缀，推送是快进，无需覆盖远程历史。
- **清理禁止重置提交者日期**：不得把作者或提交者日期改为执行时刻。一旦引入运行时刻依赖，同样的输入会产出不同的哈希链，发布历史就只能靠覆盖远程历史来对齐。
- **清理用的本机取值不得入库**：内容过滤的检索词取本机标识的实际取值（环境变量中的用户名、计算机名等），禁止把取值写进脚本、文档或提交信息。

推送必须使用完整远程 URL 与一次性凭据配置，**禁止为推送而修改仓库级或全局的 git 配置**；推送前必须确认待推送的树与工作区逐字一致（比对树哈希），并通过完整校验链。

### 推送前的敏感信息审查

- 审查对象是**派生链的全部历史**而不是当前文件树：必须逐条覆盖历史中每个版本的文件内容，以及历史中出现过的全部路径。
- 必须覆盖的类别：各类服务的凭据与令牌、私钥与证书、连接字符串、凭据关键字（含中文）、邮箱、私网地址、网络共享路径，以及**本机标识**（用户名、计算机名、域、用户目录路径、真实会话标识）。
- 必须把本机标识的**实际取值**作为检索模式（从环境变量取），不得只靠通用模式推断。
- 命中不得默认当作误报：每条都要给出实际内容的判据（例如"命令行解析的变量名""夹具里的示例地址"）；无法解释为误报的必须先清理。
- 内容清理必须**同时作用于两处**：上层仓库中该文件的当前内容（作为一次提交），以及派生链的历史。只清历史会让下一次派生把旧值重新带出来。
- 推送前必须复扫派生链，**零命中**方可推送；推送后必须抽查远程文件的实际内容，确认清理在远程同样生效。

### 版本与发布记录

- 每个发布版本必须在 `CHANGELOG.md` 中有对应版本段，并创建同名标签 `v<版本>` 与 GitHub Release；`CHANGELOG.md` 底部的版本链接与 `Unreleased` 链接必须与已创建的标签一致。
- 标签在远程创建（经 GitHub API），避免在上层仓库留下指向派生提交的引用。
- 发布说明与 `CHANGELOG.md` 的对应版本段必须一致，不得出现只在其中一处登记的能力或边界。
