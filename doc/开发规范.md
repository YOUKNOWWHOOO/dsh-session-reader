# session-reader 开发规范

本文件规定 session-reader 技能（`SKILL.md` + `scripts\` + `tests\` + `doc\` + 工程文件）开发与维护必须遵守的要求与约束。

## 定位与范围

- 本技能只读 dsh 会话历史（`~\.dsh\sessions` 与 `~\.dsh\storages`）；除写入 `--output-dir` 指定目录内的输出文件外，禁止写入、删除或修改 dsh 主目录内的任何内容。
- 运行时禁止启动 dsh、禁止联网、禁止产生模型调用、禁止读取凭据文件（`.credentials.yaml`、`.env`、含凭据的 profile 补丁）。
- 技能范围限于 `SKILL.md`、`scripts\`、`tests\`、`doc\` 与工程文件（`package.json`、`package-lock.json`、`tsconfig.json`、`biome.json`、`.markdownlint.jsonc`、`.markdownlintignore`、`.gitignore`）。技能根的 `tmp\` 是**非交付临时目录**（不受版本控制，且被仓库根 `.gitignore`、技能根 `.markdownlintignore` 与 `biome.json` 的 `files.includes` 三处排除），其中不得存放任何被规范、测试或工具依赖的内容——需要长期保留的脚本或夹具必须落在上列交付路径内。

## 语言与运行

- 脚本语言为 TypeScript（ESM，`.ts`），由 Node（v26 线）原生类型剥离直接执行；禁止引入构建步骤或提交编译产物。
- 仅使用可擦除语法：禁止 `enum`、`namespace`、参数属性、装饰器。
- 相对导入必须带 `.ts` 扩展名；类型导入必须使用 `import type`。
- 除官方格式库外零运行时第三方依赖；官方库必须经 `createRequire` 锚点解析后动态 `import()` 加载，禁止静态导入外部包（tsc 无法解析）。
- 导出函数必须显式标注参数与返回类型；禁止 `any` 与非空断言 `!`。
- 错误处理使用 Result 风格（`{success:true,data}|{success:false,error}`）；禁止空 catch；禁止 catch 后静默切换备选路径。
- 文件编码 UTF-8 无 BOM；换行 LF。

## 数据契约

- 会话日志只读；逻辑解码的唯一实现为官方 `@deepseek-ai/dsh-session-format-catalog` 公开 API（`readHeader`/`createRestore`/`decodeRow`/`finish`），全部调用收敛于 `scripts\lib\decode.ts`。
- 物理层按官方算法（结构性帧扫描）自研；禁止依赖未文档化细节。
- 解码选项固定为 `{ recovery: 'recoverable', validation: 'transformed' }`。
- 强制一致性校验：喂入 `decodeRow` 的事件行数必须等于 `finish()` 结果的事件数；不一致按数据错误处理（退出 3）。
- `readHeader` 分类为 `malformed`/`unsupported` 时必须显式失败；禁止回退或猜测。
- 坏行与尾部截断必须记入 anomalies 并在输出中显式标注；禁止静默丢弃。尾部不完整帧按 v1 策略整体丢弃并在产物中标注 `尾部未完整帧已丢弃（v1 不做前缀抢救）`；`check` 侧另标注 `tornStart` 偏移。
- 会话文件选取：同一会话目录内多代日志并存时取最高版本，同版本优先 `.zstd`。会话发现读 header 走轻量路径（按块增长读取，初始 64 KiB、逐次翻倍，上限为文件大小，只解压第一个完整帧）；完整解码解压全部帧——读取路径任一帧失败即 `数据不可读`，`check` 的结构扫描逐帧记入异常详情而不中止。
- 列表/统计元数据以 projcache 为唯一来源，使用前校验其 `version`（必须恰为 projcache 记录版本 7——与会话日志的格式版本是两套独立版本号，不得混称，后者当前取值见 `tests\fixtures.ts` 的 `CURRENT_LOG_VERSION`）与 identity 可比字段（formatVersion/createdAt/cwd/isSeeded，四项须全等）；校验失败或记录缺失必须标注"元数据不可用"并给出原因，禁止静默空值与跨源混用。
- `show` 直接解码日志，不依赖 projcache；`search` 解码日志，但范围过滤的基准（`lastPromptAt`）与命中分布的标题来自 projcache；工作区标题仅来自 `workspace.json`。
- `search --scope` 三档为单调包含关系且 `all` 为穷尽档：`text`=用户/助手正文 ＋ 问答的可读文本（单元名 `提问` 与 `回答`，抽取规则见提问与回答契约一节）；`tools`=另含工具参数与结果（含问答的原始载荷）；`all`=另含推理/系统/压缩/命令/标题请求/web 请求/交付物/待办/代理信箱 ＋ **每个事件的完整 JSON 载荷**（标签取事件类型）。`all` 档的穷尽性是"检索 0 命中 ⇒ 不存在"这一推断成立的前提，禁止在 `all` 档下遗漏任何事件记录；该穷尽性不得以任何兜底静默降级（例如序列化失败时返回空串把该事件从检索集合中悄悄移除），异常必须显性暴露并由 CLI 顶层映射为 `内部错误`。穷尽性针对**事件记录**而非原文逐字形态：载荷单元是 `JSON.stringify` 的结果，字段值中的 `"`、反斜杠与制表符呈转义形态，因此该推断只对"按记录形态出现"的关键词成立；需要逐字核对原文时用 `show --format jsonl` 导出原始事件行。默认档为 `text`，其覆盖面以本条款为准——问答的可读文本因此进入所有默认调用的命中集，这是已批准的对外行为变更。命中总数按**检索单元**计数：同一段文本在 `all` 档可能同时命中按字段枚举的单元与整条事件载荷单元而被计两次，因此 `tools`/`all` 的计数大于文本出现次数；`totalIsExact` 仅表示该数未被 `--limit` 截断，不得据此宣称"文本出现次数"。

## 提问与回答契约

本节规定 `ask_user_question`（工具向用户提问）相关消息的抽取、呈现与检索，是这类内容在全技能范围内的单一真值源；实现必须落在 `scripts\lib\ask-user.ts`，md 渲染与检索单元共用同一函数的产出。

- 判定与配对：`tool/call` 且 `data.name` 为 `ask_user_question` 的事件为提问；`data.callId` 与某 `tool/result` 的 `data.message.toolCallId` 相等者为该提问的配对回答。工具名与载荷结构由工具实现决定，抽取规则以本节登记的结构为准。
- 默认可见：默认参数（不要求 `--tools`）下，提问与配对回答必须出现在 `show` 的 md 时间线中，标签分别为 `**提问**` 与 `**回答**`；未配对的提问照常呈现，禁止因缺结果而丢弃。配对结果为错误态（`message.isError` 为 `true` 或 `data.error` 存在）时不产出 `**回答**` 条目，提问照常呈现；提问被中止或取消是正常产品形态，不是载荷异常。
- 可读文本抽取（呈现、检索单元与测试的唯一真值源）：
  - 提问：解析 `data.arguments` 得到 `questions[]`，按其顺序逐题输出，每题固定为三部分——`[<序号>] <header>（id：<id>）`、`问题：<question>`，以及每个选项一行的 `选项：<label>｜<description>`；无选项时省略选项行。
  - 回答：解析 `tool/result` 的 `data.message.content` 得到 `answers[]`，按其顺序逐条输出，每条固定为 `[<序号>] id：<id>`，其后 `selected` 非空时输出一行 `选择：<label1>、<label2>`，`custom` 为非空字符串时输出一行 `自定义：<custom>`；两者皆无时输出一行 `未作答`。
  - 字段缺失按空值契约显示 `-`；全部文本经既有载体规则隔离，并共用 `--truncate` 口径。
- 载荷异常（禁止降级）：`data.arguments` 无法解析为 `questions[]` 结构，或**非错误态**的配对结果内容无法解析为 `answers[]` 结构时，禁止原样兜底、禁止猜测补齐、禁止静默丢弃。单目标渲染（`show` 的 md，含 `--subagents` 与 `--tools`）整体失败：退出 3、stderr 单行 `错误: 数据不可读`、不产出文件；聚合检索（`search` 的各档：三档都含问答可读文本，因此同一会话在三档下都必须被排除）把该会话逐条列入 `coverage.excluded`（原因固定文本 `问答载荷结构不符合预期`）并继续，该会话不同时计入 `M`。`show --format json` 与 `--format jsonl` 不做问答抽取，因此不受本条款影响。
- 开关与过滤：这两类恒出现，不提供关闭开关；不受 `--tools` 控制（因此 `--tools` 打开时同一事件会同时以原始工具条目与问答条目出现，两者是同一事件的两种形态），不受 `--role` 影响（与工具、事件一致），仍受 `--turn`/`--seq` 范围选择与 `--head`/`--tail` 条目截取影响；它们不计入 `已隐藏 N 条工具调用/结果`。
- 检索：默认档 `text` 的检索单元包含上述可读文本，单元名分别为 `提问` 与 `回答`；问答的原始载荷仍只在 `tools` 与 `all` 档中。因此默认档的完整覆盖面是"用户与助手正文 ＋ 这类问答的可读文本"。
- 形态差异：新增标签只作用于 md；`--format json` 的 `messages[]` 仍按 `tool/call` 与 `tool/result` 分类（字段不变），`--format jsonl` 仍是逐字原文入口，`--summary` 视图不输出这两类。该差异必须同时登记在 `SKILL.md`。
- 标签词表：标签行恒为 10 个取值，含 `提问` 与 `回答`；`SKILL.md` 的标签词表、结构门禁白名单与测试断言必须与本节登记的标签取值同步。

## CLI 契约

- 子命令固定为 `list`、`show`、`search`、`stats`、`check`；每个命令只接受自己的选项集，未知或不适用选项退出 2。
- 全局选项固定为 `--dsh-home`、`--lib-root`、`--output-dir`、`--name`、`--format`、`-h/--help`。
- `--format` 取值：`md`（默认）/`json`；`show` 额外支持 `jsonl`。呈现类开关（`--role`、`--thinking`、`--tools`、`--events`、`--headers`、`--truncate`、`--turn`、`--seq`、`--head`、`--tail`、`--probe`）仅 md；`--summary` 与 `--subagents`（内容范围开关）在 jsonl 禁止（违者退出 2）。`--head` 与 `--tail` 互斥；`--summary` 与 `--turn`/`--seq`/`--head`/`--tail` 互斥；`--probe` 与 `--subagents` 互斥（`--probe` **允许**与其它呈现类开关同用：它按同一组开关渲染副本并据实报告字节数，这正是"量出带这些选项的导出有多大"的用法）。旧取值 `text` 已移除，传入即退出 2。
- 取值语义：`--limit`、`--head`、`--tail` 的 `0` 表示不限；`--truncate` 的 `0` 表示不截断；`--context` 默认 60 且按码点取命中两侧窗口；`--turn` 最小 1、`--seq` 最小 0，区间含端点。
- 解析语义：选项不可重复（重复即退出 2）；开关不接受值（`--full=1` 退出 2）；支持 `--opt=value` 内联写法；位置参数不终止选项解析；不存在 POSIX 合并短选项；`-h`/`--help` 出现在终止符之前即短路为帮助，帮助写 stdout、退出 0、不要求 `--output-dir`。
- `--name` 只接受单一路径段：ASCII 字母、数字、`_`、`-`，加全部汉字（Unicode `Script=Han`，含扩展 B 及以后，如 `𠮷`）；长度 1-64（按 UTF-16 单元）；拒绝 `.`、路径分隔符、空白、控制字符与 Windows 保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`-`COM9`、`LPT1`-`LPT9`，共 22 个）。理由：产物路径必须恒为 `--output-dir` 的直接子文件。汉字白名单必须用 `Script=Han` 属性表达，禁止改写为手写 `\uXXXX` 区间——手写区间只覆盖基本平面，会把扩展平面的正常汉字误判为非法，与"中文可用"的对外承诺矛盾。
- 支持 `--` 选项终止符：其后所有 token（含以 `-` 开头者）一律作为位置参数；帮助识别只扫描终止符之前的 token。必需选项必须写在终止符之前——`--output-dir` 落在终止符之后会被当作位置参数而报 `位置参数过多`。帮助文本与 `SKILL.md` 必须同步登记。
- 范围过滤（`--workspace`、`--since`、`--until`、`--origin`）仅作用于 `list`/`search` 与 `stats` 的全局聚合；`stats <目标>` 提供目标时与范围过滤同用即拒绝（退出 2），不做静默忽略。`search --session <标识>` 与 `search --exclude-session <标识>` 复用 `show` 目标语法，作用为该会话及其 `parentSession` 递归子树的正选与反选，与范围过滤以交集生效；两者可同时给出，此时对同一子树取交集（通常得空集）；目标不存在时按目标解析三态报错（不静默忽略）。
- 过滤项的失败与匹配语义必须区分：`--workspace` 为路径归一化全等（`\` 转 `/`、去尾部 `/`、转小写）或工作区标题全等，无任何匹配时按 `target-missing` 退出 1；`--title` 为标题子串匹配、不区分大小写，标题为 null 或元数据不可用时该会话落选，无匹配时正常返回空结果、退出 0；`--origin` 的唯一判据是 header 的 `origin` 为 `subagent`。
- `search` 与 `stats` 恒包含空会话（`includeBlank: true`），`list` 默认隐藏 `blank` 为真者且只提供 `--include-blank`；`blank` 为 null（元数据不可用）不隐藏。
- 选项表是解析、校验与帮助的单一真值源；修改 CLI 必须同步更新选项表、帮助文本、`SKILL.md` 与测试。
- 退出码：`0` 成功（含 0 命中等空结果、`--help`、`check` 无异常）；`1` 目标不存在（含前缀歧义、`--workspace` 无匹配、`--dsh-home` 不存在、`sessions` 缺失）；`2` 参数错误（含未给 `--name` 时目标已存在、前缀短于 8 字符）；`3` 数据/IO 错误（含官方格式库加载失败，其分类为 `内部错误`；以及问答载荷结构不符合预期，其分类为 `数据不可读`）。`check` 发现异常时**先落盘并打印两行 stdout、stderr 为空，再以 3 结束**，因此非 0 退出不蕴含没有产物。
- stderr 只输出单行 `错误: <分类>`；分类全集：`参数无效`、`目标不存在`、`输出文件已存在`、`输出目录创建失败`、`输出写入失败`、`输出移动失败`、`数据不可读`、`内部错误`。分类后可附一段括号说明：歧义目标附候选数（形如 `错误: 目标不存在（候选 N 个）`）；**仅组合冲突分支**附冲突选项名与**可执行的合法替代写法**（形如 `去掉 --events，或把 --format 改为 md`），替代写法用分号分隔、禁止嵌套括号；解析层与取值诊断分支只回显选项名/子命令位 token 或合法格式，不提供替代写法。说明来源固定为三处：`validateCommandOptions` 的组合约束、解析层 `parseCommandLine` 的错误文本（只回显选项名、子命令位 token 或位置参数占位名，不回显选项值）、以及固定模板的取值诊断（`--name`/`--turn`/`--seq`/`--since`/`--until`，只含选项名与合法格式，不含调用方数据；**唯一例外**是 `--name` 的 Windows 保留设备名分支，它回显命中的保留设备名（大写形式，判定不区分大小写，因此传入 `con` 时回显 `CON`）以便定位）。错误行不得包含会话内容、会话 ID、用户名与 dsh 数据路径；数据层 `StoreError.detail`（含会话目录名与绝对路径）禁止外显，仅 `argument-invalid` 的固定模板 detail 可由 `mapStoreError` 透传。
- 目标解析必须三态可区分（P7 根因修复）：唯一匹配且可读 → 执行；多个匹配（含 `session-` 前缀归一化后的精确歧义与一般前缀歧义）→ `ambiguous`/退出 1；无匹配但存在因 header 不可读而被跳过的会话目录其标识前缀匹配 → `data-unreadable`/退出 3；其余无匹配 → `target-missing`/退出 1。被跳过目录的匹配按目录名判定（header 不可读时无从取得逻辑 id）。
- 时间显示为含时区偏移的 ISO 8601 本地时间（秒级、无毫秒）；JSON 中的时间字段为原始毫秒数。过滤参数按 UTC 解析：接受毫秒数或严格 ISO，纯数字串按毫秒解释，无时区后缀按 UTC，日历或偏移越界即拒绝。
- 过滤基准是会话的"有效最近活动时间" = projcache 的 `lastPromptAt`，缺失时回落 header `createdAt`；比较双端含端点，不校验两者先后。它与产物中的 `事件时间范围`（来自事件自带 `time`）不是同一口径，两者不得互相替代。
- 空值在文本中显示 `-`，在 JSON 中为 `null`。

## 覆盖声明契约

- 每个命令的产物（md 与 json）必须让调用方判定"扫到了什么、纳入了什么、排除了什么、是否被截断"，字段与文案固定（`--probe` 产物按"规模探测"条款只含头部 KV 与三项，不含覆盖声明）：
  - md：`扫描会话 N 个；纳入 M 个；排除 K 个`，随后对每个被排除会话输出一行 `排除会话：<完整 id>（<原因>）`；`show --subagents` 另对每个归属未知的跳过项输出一行 `归属未知：<id>（<原因>）`；`search` 与 `stats` 另输出 `扫描明细：解码日志 X 份；读到事件 Y 个；解码失败 Z 份；帧解压失败 W 帧` 与 `事件时间范围：<下界> ~ <上界>`；`search` 另输出 `命中总数：X`（被截断时追加 `；已截断显示 N 条（--limit 0 显示全部）`）、`检索范围：<scope>（<覆盖面描述>）；命中总数 X 为精确值`（顺序为先 `命中总数` 后 `检索范围`）与 `## 每会话命中分布` 表格及其固定提示行；`show` 在范围选择生效时按块输出 `筛选：…；显示 X 条时间线条目（区间内事件 Y 个，共 Z 个事件）`。
  - json：`coverage: { scannedCount, includedCount, excluded: [{ id, reason }], unattributable: [{ id, reason }] }`，其中 `unattributable` 在 `show` 恒存在（未开启 `--subagents` 时为空数组）；`search`/`stats` 另含 `scan: { logsDecoded, eventsRead, decodeFailures, frameFailures, observedFrom, observedTo }`；`search` 另含 `scope`、`totalIsExact`、`distribution: [{ sessionId, type, title, hits }]`。
- 覆盖声明的 `M` 与 `K` 按命令分述，禁止用一条统一定义概括全部命令：`list` 描述发现阶段的全库覆盖——`M` 是 header 可读的会话数、`K` 是 header 不可读者，与范围过滤、空会话隐藏、`--limit` 均无关（过滤结果由合计行单独表达）；`search` 与 `stats` 描述本次作用域——`M` 是范围过滤后的会话数减去其中解码失败者，`K` 是发现阶段 header 不可读的全库会话（无从判定其是否符合过滤条件）加作用域内解码失败者；`stats <目标>` 恒为 `{1,1,[]}`；`show` 的 `N = M =` 本目标及其子树的可读节点数（未开启 `--subagents` 时为 1）、`K` 恒为 0（可归属的排除项不存在，无法归属者列入 `unattributable`）；`check` 的 `K` 恒为 0。`N = M + K` 恒成立，且实现即按 `N = M + K` 构造该声明，因此禁止在任何代码注释、文档或文案中把它表述为"调用方据此核对是否存在未列出的漏读"——它不携带超出 `M`、`K` 的信息，核对覆盖范围只能依据逐条列出的排除项。**同一会话不得同时计入 `M` 与 `K`。** `unattributable` 单独计数，不计入 `N`/`M`/`K`。
- 被排除的会话必须逐条列出，禁止合并为计数或静默丢弃。单个会话 header 不可读或解码失败不得使聚合命令（`list`/`search`/`stats`）整体失败——这会让一份损坏日志永久阻断对其余会话的浏览与检索；改为跳过并声明。单目标命令（`show`、`stats <目标>`）在目标自身不可读时显式失败（退出 3）；`show --subagents` 在任一子代理解码失败时同样显式失败，而 header 不可读的子代理无从判定归属，必须列入 `unattributable` 而非静默丢弃。
- 覆盖声明描述"本次检查了哪些会话"，与 `--limit` 无关（`--limit` 只决定产物列出多少条，由命令级摘要与产物行数表达）。`includedCount` 不得包含任何已列入 `excluded` 的会话：解码失败的会话只出现在 `excluded` 中。
- 扫描摘要的语义边界：`logsDecoded` 是成功解码的日志份数，`eventsRead` 是解码得到的事件总数，`decodeFailures` 是解码失败的日志份数（逐条在 `coverage.excluded` 中），`frameFailures` 是帧解压失败的帧数累计。`observedFrom`/`observedTo` 来自**事件自带的 `time` 字段**，禁止改用会话的"最近活动时间"（后者来自 projcache，语义不同）。
- `search` 的 `--limit` 只限制 `hits` 收集上限，`totalHits` 对纳入会话全量计数且不做提前终止；`totalIsExact` 恒为 `true`（类型即字面量 `true`，因此渲染层不得保留任何不可达的"下界"分支），其证据链为：全量计数 ＋ `scope=all` 覆盖任意事件记录的完整载荷 ＋ 未纳入会话逐条列入 `coverage.excluded`。该数的计量单位是检索单元内的匹配次数，不是文本出现次数。
- 元数据问题的逐条声明分两种粒度且不得自相矛盾：字段级判定用 `--full` 的 `**元数据**` 字段（`available && reasons.length > 0` → `部分缺失`；`!available` → `不可用`）；逐条声明行用 `元数据不完整：<完整 id>（<原因>）`（`stats <目标>` 为不带 id 的 `元数据不完整：<原因>`），因为触发条件是"存在不可用字段"（`reasons.length > 0`），既覆盖整体不可用、也覆盖可读但缺字段。禁止用 `元数据不可用` 描述后者——那会让同一会话在同一产物里被同时写成"部分缺失"与"不可用"。
- 命中分布（`distribution`）必须包含**0 命中的纳入会话**，按命中数降序、同数按会话 id 升序；其存在理由是让调用方把"自己的会话与子代理会话的命中"从结论中剔除（检索在全库上做，调查笔记与复述过的错误串都会被命中）。表格为空时不得输出该区块（空表会触发 MD055）。
- 调用方剔除自身语料的两种手段必须同时提供：产物中的逐会话分布（人工判断）与 `--exclude-session <标识>`（自动化，语义为该会话及其 `parentSession` 递归子树的反选）。

## 输出策略

- 所有命令必须显式指定 `--output-dir`（无默认值）；缺省退出 2；工具对目录位置零假定、不校验，不限制其是否位于 dsh 主目录内（唯一要求是调用方显式指定）。
- 目录不存在时创建；创建、写入或移动失败退出 3。
- 文件名：未指定 `--name` 时为 `session-reader-<命令>-<UTC 时间戳>-<随机 6 位>.<ext>`（md→md、json→json、jsonl→jsonl），指定 `--name` 时为 `<name>.<ext>`。
- 未指定 `--name` 时目标文件必须不存在；已存在时拒绝且不得改动原文件。实现为先 `existsSync` 检查、再写唯一临时文件、最后同卷 `renameSync`；"绝不覆盖"由命名唯一性（UTC 毫秒时间戳 + 随机 6 位后缀，碰撞概率 36⁻⁶/毫秒）消解，存在性检查与 rename 之间的竞争窗口在命中"同毫秒 + 同后缀"前不可触发（不改代码）。
- 指定 `--name` 时允许原子替换：Windows 的 `renameSync` 走 `MOVEFILE_REPLACE_EXISTING`，任何时刻目标文件要么是旧内容、要么是新内容；覆盖范围严格限于 `<output-dir>/<name>.<ext>`。
- 先写唯一临时文件，关闭后同卷原子移动；失败时必须清理临时文件。临时文件恒为 `.<产物文件名>.<随机 6 位>.tmp`（与目标同目录以保证同卷）。
- 输出编码固定 UTF-8 无 BOM、LF、末尾恰一个换行。
- stdout 固定两行：`完整输出已保存到: <绝对路径>` 与 `<摘要>；输出文件共 N 行`；N 必须等于输出文件实际行数；终端不显示会话正文。命令级摘要（第二行 `；` 之前的部分）必须由 `scripts\lib\render-summary.ts` 唯一产出：md 与 json 两组渲染函数都返回 `{ content, summary }`，CLI 层禁止自行拼接任何摘要文本，同一调用的摘要不得因 `--format` 不同而不同。摘要只描述产物的规模与口径，不得引入产物未支撑的断言（例如 `--subagents` 未开启时不得出现子代理数）。
- md 输出必须真实通过全局 markdownlint 基线（技能根 `.markdownlint.jsonc` 与全局基线逐条一致，只允许更严格）：禁止文件内豁免注释、禁止配置放宽、调用方无需排除输出目录；生成规则见下节"md 输出格式契约"。

## md 输出格式契约

md 渲染遵循 lint-safe 规则（f2 lint 合规 spike 定稿 R1–R5）；实现与测试的单一真值源为 `scripts\lib\render-core.ts`（载体与工具）、`render-md.ts`（聚合命令 md）、`render-show-md.ts`（show 的 md）、`render-json.ts`（JSON/JSONL）、`render-summary.ts`（命令级摘要文案）、`message-source.ts`（来源归属与来源标注）与 `ask-user.ts`（问答的可读文本抽取，md 渲染与检索单元共用），及其单元测试与 lint 门禁：

- R1 骨架与空白纪律：文件为 UTF-8 无 BOM、LF、末尾恰一个换行；标题/列表/表格/围栏/段落之间恰一个空行；标题仅用 ATX 且行首书写、文本取固定词表、无尾标点、同级唯一；加粗只作行内前缀（标签行恒以 `：` 收尾，禁止独立成段）；列表只用短横线标记且标记后恰一个空格；表格首尾管道齐全、列数一致、单元格间距统一、前后空行；围栏固定为反引号 + 语言 `text`，反引号长度 = 载荷最长连续反引号串 + 1 且不小于 3。
- R2 载体隔离：多行文本只用围栏代码块承载；单行文本只用行内代码跨度承载（反引号长度动态；内容以反引号开头或结尾时双边加一个空格内边距）；表格单元格值先经行内载体再把 `|` 转义为 `\|`；禁止任何会话来源文本以裸文本进入结构。
- 来源标注（受控例外，仅 `user/message` 事件）：`**用户**` 标签只表达模型可见角色，会把子代理中继、结算通知与插件注入显示成"用户写的"，因此凡 `user/message` 且来源不是用户本人，标签行括号内与检索命中行的 `（seq N）` 内必须追加 `来源 <kind>`。`agent-message` 与 `subagent-settled` 追加 `<senderSessionId>` 以便定位是哪个子代理，`plugin` 追加插件名，其余 kind 不加取值，`kind` 缺失、非字符串或空串时为 `来源 未标注`；空串与缺失一律按"无该字段"处理（空串没有信息量，渲染成空载体既不可读也失去标注意义）。kind 在本技能识别的词表内时裸写，词表外的值必须入行内载体原样呈现——来源种类是官方与插件共同扩展的合并联合，该词表不是完整声明，禁止丢弃、改写或把未知取值归入最接近的已知类别。**一切取自日志的取值（插件名与会话 id）都必须入行内载体**：日志字段可能含反引号或换行，裸写会把标签行拆成两行并让裸文本进入骨架。标注的判据、词表与载体处理只能由 `scripts\lib\message-source.ts` 产出，md 与 json 两条路径共用同一归属对象（json 形态为 `{ kind, form, senderSessionId, plugin }`，无值者 `null`），禁止任何渲染器自行判别来源。`**助手**`/`**推理**`/`**工具调用**`/`**工具结果**`/`**系统消息**`/`**事件**`/`**提问**`/`**回答**` 行、轮次大纲与 `--probe` 不适用该标注（各自标签已表达来源，或条目契约中没有标签行）；轮次大纲与 json `turns` 因此不含来源，这条差异必须写进 `SKILL.md`，不能让调用方在摘要视图里读到来源不明的 prompt 而无从判断。
- R3 极小归一化（唯一允许的内容改动）：CRLF 与孤立 CR → LF；制表符 → 4 空格（MD010）；行内载体首尾空白去除（MD038；全空白值保留原样）；行内载体与轮次大纲把内嵌换行折叠为空格（单行载体的前提，改变字符序列，因此必须显式登记）；当且仅当围栏载荷每个非空行都匹配 `^\s*\$\s+` 时在载荷末尾追加一行单个空格（MD014；原文各行逐字不变）。CR 归一化的必要性：会话正文可能含 CR 字节，此时产物会混入 CR，而 markdownlint 无规则可判 CR，因此它是契约层面的静默破坏而非 lint 问题（计数随门禁规模变化，故不写具体数字）。
- R4 边界：空值显示 `-`；控制字符、RTL/组合字符、零宽字符、NUL 在代码载体内原样保留；超长单行不截断（MD013 关闭）。
- R5 参考实现：规则逐字定义以 `scripts\lib\render-core.ts` 为唯一落地处，行为由 `tests\render-core.test.ts`、`render-list.test.ts`、`render-show-md.test.ts`、`render-show-json.test.ts`、`render-search-stats-check.test.ts`、`render-boundary.test.ts`、`source-annotation.test.ts`（规则单元测试）与 `tests\lint-matrix.ts`（全组合穷尽门禁）双重覆盖。历史上另有一次性 lint 合规 spike 脚本（`render-rules.mjs`），它从未进入交付路径、不得作为依据引用。
- 会话标识输出：列表、命中行与摘要行一律输出**完整会话 id**，禁止输出截断值——显示值必须与可传值同源，截断值必然引入"显示≠可用"这一整类缺陷。
- 文本载体截断：所有文本载体（用户/助手正文、推理、工具参数与结果、系统消息、`--events` 事件载荷、轮次大纲、问答的可读文本）共用同一 `--truncate` 口径，按码点截断并追加 `…`，`0` 即不截断，禁止为任何载体另设固定上限。唯一例外是每会话命中分布表格的标题列（按码点截断 40，见下条）。
- 范围选择的呈现语义：`--turn`/`--seq` 筛选事件序列（交集、含端点）且作用于每个块（子代理各自的 turn 与 seq 按自身事件流计），`--head`/`--tail` 按**条目**（标签行 ＋ 正文载体为一个单位）截取筛选后的序列且只作用于根块；子代理块因此只受 `--turn`/`--seq` 影响。筛选说明行只列**该块真正生效**的条件：`--head`/`--tail` 不是根块时不得出现，否则会出现"首 N 条；显示 M 条时间线条目（M > N）"这种同句自相矛盾的产物；`显示 X 条时间线条目` 的 `X` 必须是条目数而不是 md 行数。`筛选：` 与 `摘要：` 都是条件输出（无范围选项 / 无隐藏项时不输出）。
- 规模探测（`--probe`）：产物只含头部 KV 块与 `- 预计字节数：N`、`- 消息数：X 用户 / Y 助手`、`- 问答数：<P> 提问 / <Q> 回答`，不含任何会话正文。`P` 是本会话 `ask_user_question` 的提问事件数，`Q` 是产出回答条目的结果数（未配对的提问、以及被中止或取消的提问都不产出回答条目，因此这些情况下 `Q < P`），两者均为事件数口径，与 `--tools`、`--limit` 无关。头部 KV 含 `- 日志：` 绝对路径（自带用户名与 dsh 数据布局），`--probe` 不降低这一点，读取该产物的调用方必须按"含本地路径"处理。`N` 必须等于"以同一组选项渲染完整导出"的 UTF-8 字节数——实现方式就是真的渲染一份副本并测量，禁止用估算公式（估算要重复渲染规则，必然与真实产出漂移，而漂移会让调用方的容量判断失效）。探测只作用于主会话块。
- 每会话命中分布表格的标题列按码点截断到固定上限，避免单行无界增长。
- 子代理块层级：所有子代理块固定 H2（`## 子代理 <路径编号>`）、子内容固定 H3；嵌套关系只由路径编号表达，标题层级不随深度递进（保持实现不变；按标题层级解析的读者以路径编号判父子）。路径编号的规则必须登记到可实现的程度：各层内按子节点 1 起序号、以 `.` 连接，因此 `1.2` 是根的第 1 个子代理的第 2 个子代理。
- 技能目录的 lint 边界：技能自带 `node_modules`（开发依赖），从技能目录运行 lint 时由技能根 `.markdownlintignore` 排除；从仓库根做全量扫描时由仓库根 `.markdownlintignore` 排除（该文件同时排除 `profiles/`、`tmp/`、`.tmp/` 等第三方或临时内容）。技能自有 `.md` 文件必须全部纳入检查，禁止借 ignore 排除自有内容。技能根 `tmp\` 是非交付临时目录，必须同时被技能根 `.markdownlintignore` 与 `biome.json` 的 `files.includes` 排除——执行规范要求临时文件写入项目 `tmp\`，若该目录参与 lint 与静态分析，任何临时产物都会让校验链的前两步无故失败（实测：复核者写入的报告与探针脚本会让 `biome ci .` 与 `markdownlint-cli` 双双向非 0 退出）。

## 兼容性要求

- 官方库 API 变化只允许修改 `decode.ts` 单点适配；`--lib-root` 必须始终可覆盖默认锚点。
- 默认锚点按 dsh 自身的安装锚点探测：在 npm 缓存的 npx 目录下找同时含 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-session-format-catalog` 的 `node_modules`，命中数必须恰好 1；`<dsh-home>\profiles\node_modules` 只在它同时含这两个包时才参与（该目录自 dsh `0.1.7-rc.2` 起不再由 dsh 创建，写死它会以"官方格式库加载失败"整体失效）。无法唯一定位或库加载失败必须显式报错退出 3，并在错误说明里给出锚点或可执行的下一步；禁止静默改用其它目录。
- 格式版本由官方库 `currentVersion` 决定，产物头部显示 `v<版本>`；代码与**测试**都不得写死具体版本号对应的格式结构假设。夹具写出的日志版本由 `tests\fixtures.ts` 的 `CURRENT_LOG_VERSION` 单一维护，需要文件名版本段或 header `version` 时一律引用它——写死数字会让每次 dsh 升级打红一整批与版本无关的用例（本技能已因此实际失败过一次）。
- 事件行必须满足当前版本的结构约束，夹具据此在 `eventLine()` 内集中规范化，而不是散落在各测试文件：`time` 必须是安全整数（非整数会让该行被解码器丢弃，最终以"输入 N 行、解码得到 M 个事件"的一致性失败暴露，报错位置离根因很远）；带一级消息对象的事件必须携带字符串 `id`；工具结果的消息是"工具"角色的一级消息，`toolCallId` 与 `isError` 是消息字段而非 content 内嵌字段。夹具事件定义与该转换的分工必须保持单一来源。
- 升级到新版本日志格式时，日志的**文本抽取**必须同时兼容新旧形态：内容块可能是 `{type:"text",text}`（平铺），也可能是历史形态的嵌套块。只认一种会让抽取**静默返回空串**而不是报错（实测：只认嵌套块时，当前日志的全部工具结果事件均抽不到文本，表现为 `show --tools` 不显示工具输出、`search --scope tools` 检索不到工具结果）。兼容两种形态时不得改变既有契约：`textFromBlocks` 只计 `type` 为 `text` 且 `text` 为非空字符串的块，其行为由单元测试锁定。
- 问答的载荷结构由工具实现决定：提问的参数按 `questions[]` 的 `id`/`header`/`question`/`options` 解释，回答的结果按 `answers[]` 的 `id`/`selected`/`custom` 解释，字段结构以提问与回答契约一节登记为准；工具名或结构变化时按载荷异常条款整体失败或列入排除项，禁止静默降级为无内容。工具以错误态结果（`message.isError` 为 `true` 或 `data.error` 存在）表示提问被中止或取消，这类结果不是回答载荷，按"没有回答"处理而不是载荷异常。
- dsh 升级后必须重跑全部测试与真实数据只读抽查，并记录官方库版本。

## 安全要求

- 禁止读取 `.credentials.yaml`、`.env`、含凭据的 profile 补丁文件。
- 输出、日志与错误不得包含凭据值。
- 文件操作保持最小范围：只读会话、projcache 与 workspace 所需文件；只写 `--output-dir` 指定目录。
- 不得修改 dsh 数据；不得建立任何形式的缓存。
- 对外发布前的敏感信息审查是本节的延伸：审查对象是派生链的全部历史而不是当前文件，判据见"发布要求"。

## 测试要求

- 测试先行、负面路径必测；测试框架固定为 `node:test`。
- 覆盖率要求：行覆盖率 ≥80%、分支覆盖率 ≥85%；判定由命令行自身的阈值参数承担（`node --test --experimental-test-coverage --test-coverage-lines=80 --test-coverage-branches=85`），因此跌破阈值即让该步以非 0 退出，而不是靠人读表。
- 夹具运行时生成于 `tests\.tmp\<作用域>\`，清理时机是"该作用域被再次使用前先整体清理并重建"（`resetTempDir` ＋ `writeFixtureHome`），历史作用域不会在测试结束后自动消失；夹具不得写入仓库其它位置。夹具路径必须按测试文件自身位置解析（`import.meta.url` 锚点，如 `tests\.tmp\store\<作用域>`），禁止使用相对当前工作目录的路径——那会让"夹具只落在 `tests\.tmp`"这一不变量取决于调用方的工作目录，而 `resetTempDir` 会递归删除给定路径。夹具作用域按测试文件划分，**不保证跨进程隔离**：同一台机器上禁止并发运行两套本技能的测试——并发会让彼此的作用域目录被 `resetTempDir` 递归删除，表现为 `rmSync EPERM` 与 `test did not finish before its parent and was cancelled` 这类假失败；需要多路复核时由发起方串行安排，不给夹具增加进程级隔离（那是用项目复杂度换取一个本不该出现的场景）。
- CLI 集成测试必须使用真实官方库与合成 DSH_HOME，断言 stdout 两行契约、输出行数与摘要一致、退出码与错误分类正确；必须覆盖"显示值即可传值"（`list` 产物中的 id 直接交给 `show` 成功）、`--name` 连续覆盖、范围选择（`--turn`/`--seq`/`--head`/`--tail`）、`search --session`、以及容错声明（排除项逐条出现）。
- md 渲染规则必须有不依赖 markdownlint 的单元测试（围栏动态长度、行内跨度、四条归一化、截断口径、结构纪律）。
- 问答的呈现与检索必须有独立单元测试与集成断言：默认参数（无 `--tools`）下 md 时间线含 `**提问**` 与 `**回答**`；默认档检索能命中问答可读文本，命中行标签为 `提问`/`回答`；问答条目不受 `--tools` 与 `--role` 影响、仍受范围选择影响、且不计入 `已隐藏 N 条工具调用/结果`；`--format json` 的分类仍为 `tool/call` 与 `tool/result`；`--probe` 产出 `- 问答数：` 且计数与夹具一致；载荷结构不符时 `show` 退出 3 且无产物、`search` 把该会话列入 `coverage.excluded`；配对结果为错误态时不产出回答条目、不触发失败、不计入 `Q`，提问照常呈现。门禁夹具必须同时包含一次成对问答、一次未配对问答、一个错误态结果与一个结构不符的载荷，且错误态与结构不符必须是两个不同会话（两者期望行为不同：前者照常导出，后者整体失败）。
- 必须维护全组合 lint 门禁，入口为 `tests\lint-matrix.ts`（CLI 解析、逐组合执行、确定性复跑与汇总），其余职责分列 `tests\matrix-paths.ts`（共享锚点）、`matrix-fixtures.ts`（敌意内容集与合成 DSH_HOME）、`matrix-cases.ts` 与 `matrix-cases-query.ts`（组合词汇表与各命令组合）、`matrix-assert.ts`（结构白名单、json/jsonl 回归与 markdownlint 调用）：命令×参数组合（开关全交叉、枚举与值选项 2 路覆盖并补边界）+ 敌意字段注入夹具 + 真实只读会话；全部 md 产物统一经 markdownlint-cli 的 **JS 入口**调用（不经 `npx` 或 shell：默认从 `--workdir` 的 `node_modules` 链解析入口，可用 `--markdownlint-js` 显式指定；配置默认技能根 `.markdownlint.jsonc`，可用 `--lint-config` 覆盖），断言退出 0 且无输出；同批断言结构白名单（标题词表/围栏闭合/末尾换行/空行纪律）、json/jsonl 回归、确定性与错误路径。
- 技能目录自身的 lint 命令为 `npx markdownlint-cli --config .markdownlint.jsonc .`；`.markdownlintignore` 只排除非交付目录（开发依赖 `node_modules/`、测试临时夹 `tests/.tmp/` 与非交付临时目录 `tmp/`），技能自有 .md 文件（含本规范）全部纳入检查，禁止借 ignore 排除自有内容。lint 与门禁依赖的 `markdownlint-cli` 必须声明在 `package.json` 的 `devDependencies` 中并反映到 `package-lock.json`——工具未声明时，按锁文件重建依赖树（`npm ci`）后第八步与第十一步会直接无法运行。
- 夹具的**事件定义必须满足当前版本的结构约束**，格式规范化集中在 `tests\fixtures.ts` 的 `eventLine()`，不得散落到各测试文件：时间戳必须是安全整数（非整数会让该行被解码器丢弃，最终以"输入 N 行、解码得到 M 个事件"的一致性失败暴露，报错位置离根因很远）；带一级消息对象的事件必须携带字符串 `id`；工具结果的消息是"工具"角色的一级消息，`toolCallId` 与 `isError` 是消息字段而非 content 内嵌字段。`source.kind` 只能取具体生产者声明的取值：`plugin` 这类不带具体生产者的值会让**整条日志解码失败**（报错为"requires a producer-owned source kind"），门禁与夹具一律不得写出它。
- 全组合门禁与 CLI 共用同一套库锚点（`matrix-paths.ts` 从 `scripts\lib\paths.ts` 取，不写死 `profiles\node_modules`）与同一套夹具写入器（`fixtures.ts`），因此夹具的格式升级会同时作用于门禁；门禁在取不到库时必须立刻失败并给出可执行诊断，不得让每个组合各自失败。**门禁夹具与单元夹具必须用同一份事件转译**，禁止在 `matrix-fixtures.ts` 内另写一份事件行构造。
- SKIP 计为 FAIL；任何告警、报错或失败必须逐项记录。

## 维护要求

- 修改脚本时必须同步：`SKILL.md`、本规范、测试与夹具；并运行完整校验链（`npx --no-install biome ci .`、`npx --no-install tsc --noEmit`、`node --test`、各命令 `--help`、技能目录 `npx --no-install markdownlint-cli --config .markdownlint.jsonc .`、全组合 lint 门禁、覆盖率 `node --test --experimental-test-coverage --test-coverage-lines=80 --test-coverage-branches=85`）。其中门禁的产物路径由 `--workdir` 决定，**必须把它指向临时位置**：`node tests/lint-matrix.ts --workdir tests/.tmp/matrix --real-home <dsh 主目录>`。用技能根当 `--workdir` 会把逐组合结果、markdownlint 原始输出与九百余份产物直接写进技能根——工作区立刻变脏，且 biome 会因其中的大产物文件超过单文件体积上限而报警告（已实测）。
- CLI 必须保持默认组合可用性：除 `--output-dir`（必填）与命令目标外，所有选项必须有默认值；默认组合的可见性/格式/截断/输出行为属于对外契约，变更必须同步 `SKILL.md` 并过全套校验。
- 校验链全部通过方可提交；校验未通过时禁止以任何理由跳过、降级或放宽判定。
- 对外可观察的变更必须同步登记到 `CHANGELOG.md` 的 `Unreleased` 段；如何把 `Unreleased` 变成版本段、标签与发布记录，见"发布要求"。
- 官方库版本升级必须记录在提交信息中，并在校验链日志中留痕（本技能不产出独立的"验证记录"文件）。
- 代码注释与文档中禁止写死会随数据增长而变化的计数（会话数、事件数、产物个数等），只描述性质与判据——写死的计数必然过时并误导读者。
- 禁止保留已废弃代码路径与向后兼容垫片；不使用的代码必须删除。
- 源码与测试文件不得超过 1200 行（与全局代码编写规范一致），建议 200-600 行；拆分必须保持行为、导出签名与文案不变，并同步更新本规范、`SKILL.md` 与测试中的所有引用路径。

## 发布要求

本技能以独立仓库发布（GitHub 上的 `dsh-session-reader`），仓库根即技能根，发布内容由上层 dsh 仓库单向派生。技能本体始终在 `~/.dsh` 内开发与维护，发布不改变这一点。

### 形态约束

- **禁止在技能目录内 `git init`**：该目录由上层仓库以普通文件跟踪。在其内建仓库会让上层仓库把该目录记为 gitlink，已跟踪文件当即失去跟踪，从而形成两份互不相干的真值源。
- **禁止 submodule 或 subtree 反向引用**：技能必须同时满足"由上层仓库跟踪"与"是本机可用技能"，反向引用会让每次修改都需要在两个仓库之间对齐提交。

### 派生、清理与推送

- 派生：`git subtree split --prefix=skills/session-reader` 取技能目录的提交链。
- 清理：对派生链做去标识化，并把提交身份统一为 GitHub 的 noreply 地址。
- 推送：`git -c credential.helper=… push <完整远程 URL> <分支>:main`。

三条硬性要求：

- **派生与清理必须是输入的确定性函数**：同一条命令重跑两次必须得到相同的提交哈希链。满足该判据时，上层仓库追加新提交后重新派生与清理的结果以既有发布链为前缀，推送是快进，无需覆盖远程历史。
- **清理禁止重置提交者日期**：不得把作者或提交者日期改为执行时刻。一旦引入运行时刻依赖，同样的输入会产出不同的哈希链，发布历史就只能靠覆盖远程历史来对齐。
- **清理用的本机取值不得入库**：内容过滤的检索词取本机标识的实际取值（环境变量中的用户名、计算机名等），禁止把取值写进脚本、文档或提交信息。

推送必须使用完整远程 URL 与一次性凭据配置，**禁止为推送而修改仓库级或全局的 git 配置**；推送前必须确认待推送的树与工作区逐字一致（比对树哈希），并通过完整校验链。

### 推送前的敏感信息审查

- 审查对象是**派生链的全部历史**而不是当前文件树：必须逐条覆盖历史中每个版本的文件内容，以及历史中出现过的全部路径。
- 必须覆盖的类别：各类服务的凭据与令牌、私钥与证书、连接字符串、凭据关键字（含中文）、邮箱、私网地址、网络共享路径，以及**本机标识**（用户名、计算机名、域、用户目录路径、真实会话标识）。
- 必须把本机标识的**实际取值**作为检索模式（从环境变量取），不得只靠通用模式推断。
- 命中不得默认当作误报：每条都要给出实际内容的判据（例如"命令行解析的变量名""夹具里的示例地址"）；无法解释为误报的必须先清理。
- 内容清理必须**同时作用于两处**：上层仓库中该文件的当前内容（作为一次提交），以及派生链的历史。只清历史会让下一次派生把旧值重新带出来。
- 推送前必须复扫派生链，**零命中**方可推送；推送后必须抽查远程文件的实际内容，确认清理在远程同样生效。

### 版本与发布记录

- 每个发布版本必须在 `CHANGELOG.md` 中有对应版本段，并创建同名标签 `v<版本>` 与 GitHub Release；`CHANGELOG.md` 底部的版本链接与 `Unreleased` 链接必须与已创建的标签一致。
- 标签在远程创建（经 GitHub API），避免在上层仓库留下指向派生提交的引用。
- 发布说明与 `CHANGELOG.md` 的对应版本段必须一致，不得出现只在其中一处登记的能力或边界。
