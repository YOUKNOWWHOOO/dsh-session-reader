## 结论摘要

| 编号 | 问题 | 严重度 | 影响的调用方 |
| --- | --- | --- | --- |
| P1 | `list` 显示的短 id 与 `show` 要求的前缀长度不一致 | 高 | 所有按显示值取会话的调用 |
| P2 | `search` 的 `--limit` 截断命中总数本身 | 高 | 所有依赖命中计数的判断 |
| P3 | `search` 不索引事件数据，且未声明该边界 | 高 | 所有"检索 0 命中 ⇒ 不存在"的推断 |
| P4 | 每次调用强制新建不可命名、绝不覆盖的输出文件 | 中 | 批量调用与产物清理 |
| P5 | 缺少面向 agent 的范围选择能力 | 中 | 读取大型会话、限定范围检索 |
| P6 | 参数错误的退出码与文档不一致 | 中 | 自动化调用方 |
| P7 | 对存在的会话返回"目标不存在" | 中 | 全量扫描类任务 |
| P8 | 选项互斥面偏窄而组合多，易踩 | 低 | agent 首次调用 |

## P1 `list` 显示的短 id 与 `show` 要求的前缀长度不一致

- 现象：`list` 输出的短 id 为 4 字符（如 `session-fc53`），而 `show` 要求前缀至少 8 字符。
- 证据：`list --title dsh` 输出 `session-fc53`；`show fc53` 返回 `错误: 参数无效（会话前缀至少 8 个字符）`（exit 2）。
- 影响：照抄界面上显示的标识符必然失败，调用方必须先 `list --format json` 再取完整 id，多一次往返。
- 期望行为：显示的 id 可直接使用——二选一即可：`list` 输出完整 id，或 `show` 接受所显示的短 id。

## P2 `search` 的 `--limit` 截断命中总数本身

- 现象：`--limit` 不只是限制显示条数，还截断了"命中总数"这一统计量。
- 证据：以 `--limit 5000` 复跑后，13 个检索词的命中数发生变化（`old_string` 346 变为 357、`not found` 100 变为 109）。
- 影响：调用方把下界当成精确值，进而对"某现象出现几次""某词是否常见"作出错误判断。
- 期望行为：命中总数与 `--limit` 解耦；无法解耦时，输出必须显式标注该数字是下界。

## P3 `search` 不索引事件数据，且未声明该边界

- 现象：`search` 只覆盖文本面，事件载荷（生命周期事件、错误事件、工具调用与结果）不在检索范围内；输出与 SKILL.md 均未声明这一点。
- 证据：会话 `session-77707026` 的日志含 44 行 `data_inspection_failed`，而 `search data_inspection_failed` 对该会话 0 命中。
- 影响：最危险的误用是把"0 命中"读成"不存在"。本次调查中该陷阱一度直接导致错误的覆盖结论（"其余会话未出现"）。
- 期望行为：二选一——把事件载荷纳入检索；或在输出尾部与 SKILL.md 中显式声明检索范围仅为文本面，并禁止把 0 命中表述为不存在。

## P4 每次调用强制新建不可命名、绝不覆盖的输出文件

- 现象：`--output-dir` 下的产物文件名由工具生成（时间戳加随机后缀），调用方既不能指定名字，也不能覆盖自己上一次的产物。
- 证据：本次两项调查在 `C:\Users\ZHANG\.dsh\tmp` 下产生 120 个以上 `session-reader-*` 产物，查找与清理成本高。
- 影响：批量调用污染共享临时目录；调用方无法用稳定路径引用"我上一次的导出"；与"长报告落盘"的 agent 约定叠加后，产物数量线性增长。
- 期望行为：允许指定产物 basename（如 `--name <basename>`），或允许覆盖调用方自己的同名产物，或按调用方给定前缀归入子目录。

## P5 缺少面向 agent 的范围选择能力

- 现象：`search` 没有按会话限定的选项；`show` 没有 turn/seq 区间，也没有 `--head`/`--tail`；`--truncate` 是全局量，无法按角色区分。
- 证据：本次为读取一个 1.2 MB 的会话，只能整份导出（262,551 字节、3,778 行）后自行切片。
- 影响：读取大型会话必须付出整份导出的成本；"只看某个会话内某几个 turn"这类最常见的调查动作没有直接表达方式。
- 期望行为：`search` 支持限定单个会话；`show` 支持 turn 或 seq 区间与首尾截取；`--truncate` 支持按 `user`/`assistant` 分别设置。

## P6 参数错误的退出码与文档不一致

- 现象：互斥选项组合的退出码与文档声明的分类不一致。
- 证据：`--format json` 与 `--events` 同时使用（互斥）时实测 exit 1，而文档声明参数错误应为 exit 2。
- 影响：自动化调用方按退出码分流时会走错分支。
- 期望行为：实现与文档对齐，并明确哪一侧是权威。

## P7 对存在的会话返回"目标不存在"

- 现象：对确实存在的会话，`show` 返回 `错误: 目标不存在`。
- 证据：会话 `session-a3b7d6c5` 在本次全量扫描中复现一次（同一批量调用中的其它会话正常）。
- 影响：全量扫描类任务会漏掉会话，且调用方无法区分"真不存在"与"读取失败"。
- 期望行为：查明成因（日志损坏、投影缓存不一致或其它）；无法读取时给出可区分的错误分类。

## P8 选项互斥面偏窄而组合多，易踩

- 现象：`--format json|jsonl` 与全部呈现类开关互斥，`jsonl` 另与内容范围开关互斥；组合数量多，正确组合不易记住。
- 证据：本机在前序会话中已修复文档缺失（SKILL.md 已登记互斥规则），但调用仍踩到 exit 2。
- 影响：一次误用即浪费一次完整调用（含产物落盘）。
- 期望行为：在保持现有契约的前提下，让错误信息同时给出该组合的合法替代写法。

## 优化建议（面向 agent 的可用性）

1. 让"显示值"与"可传入值"同源（对应 P1）——这是唯一会让新调用方首次调用必然失败的缺陷，优先级最高。
1. 让统计量与显示量解耦，并让每次输出的边界可自证（对应 P2、P3）：命中总数、检索覆盖范围、是否被截断，都应在产物中以固定字段给出，使调用方无需读源码即可判断结论强度。
1. 让产物路径可控、可复用（对应 P4）：agent 会连续调用数十次，稳定的命名或覆盖语义直接决定后续步骤能否引用。
1. 补齐范围选择能力（对应 P5）：区间与首尾截取能把"读整个会话"变成"读需要的部分"，这是大型会话调查的主要成本来源。
1. 统一错误契约（对应 P6、P7、P8）：分类稳定、可区分、可自诊，是自动化调用方正确分流的前提。
1. 在 SKILL.md 中为每个子命令显式声明"覆盖范围"与"统计口径"两个小节，把当前的隐性边界变成显式契约。

## 验收标准

- P1：用 `list` 输出的短 id 直接调用 `show` 成功（exit 0），无需先取完整 id。
- P2：同一关键词在不同 `--limit` 下命中总数一致；若无法保证，产物中含显式的下界标注。
- P3：`search` 对已知含目标字符串的事件载荷命中非空；或产物与 SKILL.md 均显式声明范围仅文本面。
- P4：连续两次调用可以写入同一路径（覆盖）或按调用方指定的 basename 写入。
- P5：存在"只读某会话某 turn 区间"与"只检索某会话"的可用调用，且不产生整份导出。
- P6：互斥组合的退出码与文档一致，且实测覆盖该组合。
- P7：`session-a3b7d6c5` 这类会话要么可读，要么给出与"不存在"可区分的错误。
- P8：误用互斥组合时，错误信息包含合法替代写法。
- 回归：技能自带测试全部通过且无跳过；产物通过全局 markdownlint 基线；命令仍为离线只读。

## 约束与不可破坏项

- 离线、只读：不运行 dsh、不联网、不读取凭据。
- 产物格式契约：md 产物必须继续通过全局 markdownlint 基线（`~/.dsh/全局规范/配置文件模板/.markdownlint.jsonc`）；json/jsonl 为机器可读格式，不参与 lint。
- 退出码体系保持 0/1/2/3 四态语义，只能修正不一致，不得删减分类。
- 不引入缓存作为默认策略；确需引入时必须先取得用户同意并说明失效策略。
- 保留现有能力：逐帧解压 zstd 多帧日志、事件级导出、子代理块与路径编号表达。
