# dsh-session-reader

> 读取、列出、检索、统计与校验本机 DeepSeek Harness（下称 dsh）的会话历史，包括子代理会话；全程只读、离线、不产生模型调用。

## 背景与目的

dsh 会把每一次会话完整落盘，包括用户与助手的往来消息、模型推理、工具调用与工具结果、生命周期事件、以及子代理各自的会话。这些日志既是排查问题的第一手材料，也是复盘模型行为的唯一依据。但 dsh 自身不提供读取它们的命令：要查看一次会话，只能手工定位 `sessions/` 下的目录、解压多层 zstd 帧、再逐行解析 JSON 事件。

这个技能解决的就是这件事。它把会话日志的定位、解压、解码与呈现收敛成五个命令，并且刻意做了三个设计取舍：

- **只读且有边界**：只读 dsh 主目录下的会话日志与投影缓存，只写 `--output-dir` 指定的目录，不启动 dsh、不联网、不产生模型调用、不读取任何凭据文件。
- **结果落到文件而不是终端**：会话正文动辄数万字符，直接打到终端既无法阅读也无法处理。所有命令把产物写入文件，终端只回两行——产物路径与规模摘要。
- **结论必须能判断强度**：任何一份产物都自带覆盖声明，写明扫描了哪些会话、纳入了哪些、排除了哪些、为什么排除。这样使用者能知道一份"没有命中"的结果到底是确实不存在，还是根本没扫到。

## 适用环境

- **平台**：Windows。技能的路径处理、输出文件名校验与文件移动语义都按 Windows 实现（例如拒绝 `CON`、`PRN`、`NUL`、`COM1`-`COM9`、`LPT1`-`LPT9` 这 22 个保留设备名）。
- **Node.js**：v26 线。脚本是 TypeScript（ESM），由 Node 的原生类型剥离直接执行，**没有构建步骤**，也不需要 `tsconfig.json` 参与运行。
- **dsh**：本机需有一份可用的 dsh 安装，因为技能需要两样东西——会话数据本身，以及 dsh 随发行版提供的官方会话格式库 `@deepseek-ai/dsh-session-format-catalog`。
- **主目录**：默认取环境变量 `DSH_HOME`，未设置时取 `~/.dsh`；可用 `--dsh-home` 覆盖。该目录不存在、或其下缺 `sessions/` 时，命令以退出码 1 结束。

## 功能

技能提供五个命令。它们的共同点是：只读，产物写文件，成功时终端只回两行。

### `list`：列出会话

列出本机全部会话（或符合过滤条件的会话），每行一个会话，给出 id、标题、工作区、最近活动时间、轮次、类型与日志大小。

- 过滤：按工作区（路径归一化全等匹配或标题全等匹配）、按时间区间、按标题子串、按来源（主会话／子代理）。
- 排序：按最近活动时间、创建时间、标题、大小或轮次。
- `--full`：把表格换成逐会话的完整块，额外给出 cwd、预设、模型、令牌用量与元数据可用性。
- 默认隐藏空会话，用 `--include-blank` 显示。

### `show`：读取一次会话

把一次会话的时间线渲染出来：用户与助手的正文、模型推理、工具调用及其参数、工具结果、系统消息与生命周期事件。

- 默认隐藏推理、工具与生命周期事件，用 `--thinking`、`--tools`、`--events` 分别显示；摘要行会告诉你有多少条被隐藏。
- `--summary` 只给轮次大纲（每轮一问一答各截取一段），适合先看整体再决定读哪一段。
- 范围选择：`--turn`/`--seq` 按事件序列筛选（作用于每个块），`--head`/`--tail` 按条目截取（只作用于主会话块）。
- `--headers` 给每行标注事件序号与本地时间；`--truncate N` 按码点截断正文。
- `--subagents` 连带把子代理会话按父子层级一并渲染，路径编号（如 `1.2`）表达嵌套关系。
- `--probe` 先量规模：只给会话头、预计正文字节数与消息条数，不落任何正文，用于决定值不值得完整读取。

### `search`：检索会话内容

在全库会话里检索关键词，产物给出命中总数、每会话命中分布与逐条命中（含上下文片段）。

- `--scope` 三档：`text` 只搜用户与助手正文；`tools` 另含工具调用参数与工具结果；`all` 为穷尽档，另含推理、系统消息、压缩摘要、命令、标题请求、交付物、待办与每个事件的完整 JSON 载荷。
- 命中分布逐会话给出命中数（含 0 命中的会话），用途是把**使用者自己**的会话从结论里剔除——检索在全库上做，你自己在这个技能里讨论过的内容也会被命中。
- `--exclude-session` 直接排除某个会话及其子代理子树；`--session` 反过来只在该子树内检索。
- 不区分大小写匹配是默认行为，`--case-sensitive` 切换为区分。

### `stats`：统计用量

给出会话数、轮次、步数、工具调用数、令牌用量（未缓存输入／输出／缓存读／缓存写）、时间跨度与日志总大小。给目标时统计单会话，不给目标时做全局聚合。

### `check`：校验日志完整性

逐会话核查日志的结构：格式版本、结构是否完整、zstd 帧数与行数、事件序号是否连续、坏行数、尾部是否被截断，以及异常详情。用于回答"日志有没有损坏、损坏在哪一步"。不给目标时校验全库，且这种扫描不读会话头，因此连头都读不出来的会话也在诊断范围内。

## 使用方法

### 前置条件

1. 本机已安装并至少使用过一次 dsh（需要有 `~/.dsh/sessions/` 下有会话日志）。
1. `node --version` 返回 v26 线。
1. 把本仓库放在 dsh 的技能目录下，或任意位置直接调用脚本（脚本按自身位置解析资源，不依赖当前工作目录）。

若作为 dsh 技能使用，目录应放在 `<dsh-home>/skills/session-reader/`，这样会话创建时它会被技能目录收录，模型可以按名称加载它。

### 基本调用

所有命令都必须显式给出 `--output-dir`（无默认值，缺省即退出码 2）。惯例是项目临时目录。

```powershell
# 列出最近活动的 20 个会话
node scripts/session-reader.ts list --output-dir .\tmp --limit 20

# 只看某个工作区的会话，按大小排序
node scripts/session-reader.ts list --output-dir .\tmp --workspace "C:\Users\me\project" --sort size

# 读取最近活动的主会话（默认隐藏推理与工具）
node scripts/session-reader.ts show last --output-dir .\tmp

# 先量规模，再决定是否完整读取
node scripts/session-reader.ts show last --output-dir .\tmp --probe

# 完整读取，含推理、工具调用与参数、工具结果，并标注事件序号与时间
node scripts/session-reader.ts show last --output-dir .\tmp --thinking --tools --headers

# 只看第 3 到第 5 轮的对话
node scripts/session-reader.ts show last --output-dir .\tmp --turn 3-5 --role user

# 连带子代理会话一起渲染
node scripts/session-reader.ts show last --output-dir .\tmp --subagents --format json

# 全库检索某个错误串，含所有事件载荷
node scripts/session-reader.ts search "ECONNRESET" --output-dir .\tmp --scope all

# 检索时排除自己这次会话及其子代理
node scripts/session-reader.ts search "timeout" --output-dir .\tmp --scope all --exclude-session last

# 全局用量统计
node scripts/session-reader.ts stats --output-dir .\tmp

# 校验全库日志完整性
node scripts/session-reader.ts check --output-dir .\tmp
```

### 指定产物名

不给 `--name` 时，产物名是 `session-reader-<命令>-<UTC 时间戳>-<随机 6 位>.<扩展名>`，且**同名文件已存在就拒绝执行**（退出码 2），因此不会覆盖已有产物。给 `--name` 时产物固定为 `<output-dir>/<name>.<扩展名>`，同名产物被原子替换（会覆盖上一次的内容）。

`--name` 只接受单一路径段：ASCII 字母、数字、`_`、`-`，以及全部汉字（含扩展 B 及以后）。长度 1-64。

### 目标写法

`show`、`stats`、`check` 以及 `search --session`/`--exclude-session` 都接受三种目标写法：

- 完整会话 id，如 `session-3f2a1c4e-...`；
- 唯一前缀（不区分大小写，最少 8 个字符，可省略 `session-`），如 `3f2a1c4e`；
- `last`，表示最近活动的主会话（区分大小写）。

前缀有歧义时会以退出码 1 报错并给出候选数，改用更长前缀即可。

## 输出格式

### 两种格式

- `md`（默认）：面向人阅读的 Markdown，结构固定、可被 Markdown 工具继续处理。
- `json`：面向程序的结构化结果，含覆盖声明、扫描明细与逐条数据。
- `jsonl`：仅 `show` 支持。首行是官方库归一化后的会话头，其后每行一个已解码事件，是**逐事件穷尽枚举**的唯一入口。

`json`/`jsonl` 与 Markdown 专用选项（`--thinking`、`--tools`、`--role`、`--truncate`、`--turn`、`--seq`、`--head`、`--tail`、`--headers`、`--probe`）互斥，同时给出即退出码 2。

### 终端只回两行

```text
完整输出已保存到: <产物绝对路径>
<规模摘要>；输出文件共 N 行
```

摘要给的是该命令的关键计数（会话数、命中数、事件数等），且同一调用不因 `--format` 而改变。失败时终端不输出任何内容，只在 stderr 打一行 `错误: <分类>`。

### 产物编码

UTF-8 无 BOM、LF 换行、末尾恰一个换行。Markdown 产物满足一套可被 lint 校验的结构纪律（标题词表固定、多行文本只用围栏承载、单行文本只用行内代码承载、围栏长度按内容动态计算），因此**调用方不需要把输出目录排除在 Markdown 静态检查之外**。

### 覆盖声明

每份产物都写明"扫了什么、纳入了什么、排除了什么"：

```text
扫描会话 12 个；纳入 11 个；排除 1 个
排除会话：session-9f1c...（header 不可读）
```

三个数字满足 `扫描 = 纳入 + 排除`，且实现就按这个等式构造。**它不是独立的核对手段**——要判断覆盖范围是否完整，看的是逐条列出的排除项与原因。单个会话损坏不会让整份统计失败：聚合命令跳过它并声明，只有以它为目标的单目标命令才会明确报错。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功，含 0 命中、空结果、`--help`、`check` 未发现异常 |
| 1 | 目标不存在，含前缀歧义、`--workspace` 无匹配、`--dsh-home` 不存在、`sessions/` 缺失 |
| 2 | 参数错误，含 `--name` 非法、选项组合违规、缺 `--output-dir`、前缀短于 8 字符、未给 `--name` 时产物已存在 |
| 3 | 数据或 IO 错误，含 `check` 发现异常、输出目录创建失败、输出写入失败、产物移动失败、官方格式库加载失败 |

stderr 的格式固定为一行 `错误: <分类>`，分类是固定的 8 个取值（`参数无效`、`目标不存在`、`数据不可读`、`内部错误`、`输出目录创建失败`、`输出文件已存在`、`输出写入失败`、`输出移动失败`）。分类后可能附一段括号说明；调用方应只依赖分类与退出码分流，括号说明的内容可能扩展。

一个例外需要知道：`check` 发现异常时**先落盘并打印两行 stdout，再以 3 结束**，stderr 为空。因此退出码 3 不代表没有产物。

## 已知边界与限制

这些是实际存在的限制，使用前应当知道：

- **与 dsh 的格式版本绑定**。会话日志的格式由 dsh 决定，技能通过官方格式库解码，格式版本以官方库的 `currentVersion` 为准（当前为 v4）。dsh 升级改变了会话格式时，技能的夹具与断言需要同步更新，本技能已在 dsh `0.1.7-rc.2` 上适配并验证。
- **依赖官方格式库的位置**。库随 dsh 一起安装。技能默认按 dsh 自身的安装锚点探测它（在 npm 缓存的 npx 目录下找同时含 `@deepseek-ai/dsh` 与该库的 `node_modules`，命中数必须恰好一个），也可以用 `--lib-root` 显式指定含 `@deepseek-ai` 的 `node_modules` 目录。探测不到时不会猜测，而是直接以退出码 3 报错并说明该指定什么。
- **平台限定 Windows**。在其它平台上，输出文件名的保留设备名校验、路径处理与原子替换语义都未经验证。
- **检索的穷尽性有一处细节**。`--scope all` 档的"事件载荷"单元是事件的 JSON 序列化结果，其中的双引号、反斜杠与制表符会以转义形态出现。因此只存在于非文本字段里、且含这些字符的关键词可能命不中；需要逐字核对原文时用 `show --format jsonl` 导出原始事件行。另外命中总数是**检索单元内的匹配次数**，不是文本出现次数，同一段文本可能被计多次。
- **元数据可能不可用**。列表与统计的部分字段来自 dsh 的投影缓存。缓存缺失、版本不符或与会话身份不一致时，相关字段标注为"元数据不可用"并在 json 中给出原因，不会静默填 0。
- **产物含会话明文**。产物是会话内容的导出，应按临时产物管理，不要提交到公开仓库。

## 开发

### 目录结构

```text
SKILL.md          技能说明：触发条件、命令契约、输出格式、退出码（写给加载它的模型看）
README.md         本文件：面向使用者的总览
scripts/          实现
  session-reader.ts   CLI 入口：解析、校验、分发、落盘
  lib/decode.ts       官方格式库加载、事件解码、各类文本抽取
  lib/frames.ts       物理层：结构性 zstd 帧扫描与逐帧解压
  lib/store-*.ts      会话发现、投影缓存元数据、列表、检索、统计、校验
  lib/render-*.ts     md/json/jsonl 渲染与命令级摘要
tests/            单元测试、CLI 集成测试、md 渲染单元测试、全组合 lint 门禁
doc/开发规范.md    开发与维护要求（契约、边界、测试与校验链）
```

### 校验链

修改代码后依次运行（在技能目录下）：

```powershell
npm ci
npx --no-install biome ci .                    # 格式化与 lint
npx --no-install tsc --noEmit                  # 类型检查
node --test tests                              # 测试
node tests/lint-matrix.ts --workdir tests/.tmp/matrix --real-home $env:USERPROFILE\.dsh   # 全组合 lint 门禁
npx --no-install markdownlint-cli --config .markdownlint.jsonc .
node --test --experimental-test-coverage --test-coverage-lines=80 --test-coverage-branches=85 tests
```

门禁的产物路径由 `--workdir` 决定，必须指向临时位置，否则会把上千份产物与合成夹具写进技能目录。

### 测试无法脱离 dsh 数据

`tests/` 里的 CLI 集成测试与全组合门禁需要**真实的官方格式库**（以及门禁的真实会话抽查）。库定位不到时这些测试不会静默跳过，而是直接失败并说明原因——因为跳过会让"没有通过"伪装成"通过"。
